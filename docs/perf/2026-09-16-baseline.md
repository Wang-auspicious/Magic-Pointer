# Performance baseline — 2026-09-16

Harness: ad-hoc probes committed alongside each measurement. All numbers are
from this machine (Windows 11), measured with the repo's own scripts.

## P1 — pointer input state stream (`scripts/pointer_input_state.ps1`)

The script sleeps `Start-Sleep -Milliseconds 35`, i.e. it intends ~28.6 Hz.
Measured over 8s by `node tools/measure_poller_rate.js` (timestamps each stdout line
from the spawned process):

```
samples=47 over 8079ms
gap p50=63.1 p90=74.2 p99=110.3 max=110.3
effective_hz=15.6
```

**15.6 Hz actual against an intended 28.6 Hz.** p99 gap 110ms.

This stream is the sole source of `pointerInputState` in `electron/main.ts`
(buttons / foregroundApp / foregroundHwnd / isWindowMoving / scrollDelta /
swallowingLeft / captureArmed). It feeds:

- wiggle wake detection (`WAKE_DETECTION` budget = **50 ms**)
- mouse-side-button activation
- temporary-surface dismiss-on-click
- pass-through gesture chaining

A 50 ms budget sampled at a 63 ms median gap cannot be met — wake is decided on
stale state, and a fast wiggle or click can fall entirely between samples.

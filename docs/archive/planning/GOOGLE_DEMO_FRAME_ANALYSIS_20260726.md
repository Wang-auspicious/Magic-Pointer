# Magic Pointer 演示视频逐帧交互分析

日期：2026-07-26

## 结论

仓库内四段演示的共同交互不是“动作栏 + 输入框 + 麦克风 + 发送按钮”，而是一条非常
克制的单气泡状态机：

```text
不可见
  → 小圆/声纹
  → 语言的部分转写逐段出现
  → 同一个气泡随转写横向增长
  → 同一个气泡显示 Processing
  → 只有结果需要承载内容时才展开结果卡
```

因此本项目的临时交互面必须保持单一。语音还是文字不是每次唤醒后再问用户，而是在
Dashboard 中预先确定。临时气泡不承载设置、候选动作、Agent 选择或多余按钮。

## 检查方法

- 输入：仓库根目录 `演示7.webm`、`演示8.webm`、`演示9.webm`、`演示10.webm`。
- 四段视频约为 24 fps，每段约 15–19 秒、约 429 帧。
- 先以每秒一张建立时间线，再回到状态发生变化前后的相邻帧核对。
- 生成的接触表保存在 `data/runtime/video-frame-review-20260726/`，只作为本地开发证据。
- 下列帧号用于说明状态转换；视频编码中的展示帧可能存在一帧左右偏差。

| 帧 | 约时间 | 可见状态 | 交互含义 |

| 312 | 13.00 s | `Double t…` | 后续命令仍复用同一形态 |

## 演示 8

可见的语言阶段依次包括 `Move this…`、`to here`、`Make this as…` 和
`put a bird here`。对象指代与空间目标由指针关系承担，UI 没有另外展示对象选择面板。
多个动作之间反复回到小圆，再由新转写扩展。

## 演示 9

可见短语包括 `Merge thes…`、`Make this more human` 和 `Make this softer`。
不同任务类型没有换成不同工具条；同一气泡通过语言和当前对象完成路由。

## 演示 10

| 帧 | 约时间 | 可见状态 | 交互含义 |
|---:|---:|---|---|
| 96 | 4.00 s | 小圆/声纹 | 唤醒后的最小状态 |

## 没有在演示中看到的元素

- 独立麦克风按钮；
- 关闭按钮；
- 发送按钮；
- 三个建议动作；
- “选择语音/文字”的临时切换；
- Agent 下拉列表；
- 对象详情卡；
- 常驻 Dashboard 或浮标。

这些元素即使各自“有功能”，同时出现在临时提示框里也会破坏演示所体现的直接性。
它们只能放进 Dashboard、无障碍备用路径或结果确认面。

## 已落地的界面合同

1. `voice` 模式初始宽度 72 px，只显示声纹；
2. `text` 模式初始宽度 176 px，只显示文字入口；
3. Canvas 测量实际转写/输入宽度，窗口在 72/176 px 到 560 px 之间逐步变化；
4. partial transcript 每次到达都更新同一个输入值并重新计算宽度；
5. final transcript 按 Dashboard 的 `voice_auto_submit` 决定是否自动提交；
6. `Processing…`、错误和完成状态均复用同一气泡；
7. Escape 作为无障碍关闭方式，但不显示关闭按钮；
8. 模式选择、静音间隔、灵敏度和禁用应用只在 Dashboard 设置。

## 0. 一句话结论

> **所有人都在让 AI 去用鼠标。我们让鼠标去喂 AI。**

这不是一句口号，是成本、隐私、速度三条曲线同时被反转的结构性选择。下文给出证据。

## 1. 外部调研：行业赌注正在同一个地方失败

### 1.1 失败点不是"理解"，是"定位与执行"

**事实**｜36氪评腾讯 QClaw（2026-08）：装齐所有 Skill、授予辅助功能/录屏/文件全部权限后，它能打开微信、能点开搜索框，**就是发不出一个文件**；调用小红书 Skill 时卡在二维码，连把登录页拉起来让用户扫都做不到。
原文的定性最关键：

> 今天的操作系统有两套接口：给普通人用的 GUI 和给开发者用的 CLI。但没有一套是专门为 Agent 设计的。**Agent 在用「人类的界面」，做「机器的事情」。**
> 一旦进入执行阶段……它不知道当前界面是否真的打开，不知道点击是否生效，更无法确认输入是否正确。所有动作，本质上还是猜一个「最可能的下一步」。
> — https://www.36kr.com/p/3728581722092039

**事实**｜OSWorld 基准（369 个真实桌面任务）：**人类 72.36%，最强 agent（Operator）38%**，GPT-4V baseline 仅 12.24%，缺陷集中在 "GUI grounding 与跨应用工作流推理"。
**事实**｜单张截图在多数模型上消耗 **15,000+ tokens**；视觉推理延迟显著高于文本。
— https://zylos.ai/research/2026-02-08-computer-use-gui-agents/

**事实**｜腾讯 Marvis 深度评测：优点是批量脏活；短板是"偶发感知幻觉"与"频繁硬垂询"（每个关键操作都要确认，啰嗦）。
— https://www.neican.ai/insights/marvisai-20260528111004101-0/

**推断**：computer-use 这条路上，模型花 15k token + 数秒，做的是一件**人手 200ms 免费就能做完、且 100% 准确**的事——指出"哪个"。这不是模型能力问题，是分工分配错误。

### 1.2 而"指"这件事，社区已经说得非常清楚

Google DeepMind 发布 AI Pointer 后的 HN 讨论（1113 条），是这个品类最对口的一手民意。
— https://news.ycombinator.com/item?id=48111581

**支持我们方向的（原文摘录）**：

- 「如果你要说的东西已经在屏幕上，**指着它说"这个"比描述它容易得多**。而如果是文件这种抽象实体，你根本没法描述——除非把整条路径念一遍。」
- 「随便找张车流照片，指定某辆车的某个轮胎——你要用多少词才能说清？换成鼠标一圈就完了。**指点/圈注是压倒性地更好。**」
- 「我一直想要的就是：**一边点一边和 LLM 连续对话**。有时我要去另一个页面截图，有时我在翻文件，有时我在高亮日志行。」← 这条几乎是逐字描述我们的产品
- 「最小可行的本地版是什么？也许是文件系统——悬停任何文件，直接给我一两句话说明这是什么。**这能解决那个永远解决不了的问题：找到那一份文档。**」

**打脸我们当前设计的（必须正视）**：

- 语音是**重复出现的最大反对意见**，至少 6 条独立高赞：
  - 「我看到那个图片编辑 demo 需要麦克风，直接关掉了。**如果做成 Spotlight 那样打字的弹窗**，在办公室/社交场合就能用。」
  - 「我不想跟电脑说话。是的我很确定。SuperWhisper 能离线我知道——**问题不是它不够好，是我不想要。**」
  - 「99% 的办公室是开放式的。听每个人对着电脑说话？做这东西的人是不是都独居。」
- 隐私：「**如果它要往 Google/OpenAI 家里打电话，那就算了。** 我不想让这些公司常连我的操作系统。」
- 速度：「改一个数字花 5 秒、把一行文字拖到另一个框花 10 秒——这种东西不该拿出来 demo。」
- 价值门槛：「大部分示例右键菜单就能做完。」
- Google 的 demo 本身当场翻车：「它根本没跟踪我圈的范围，只认鼠标最后落点，还说'好的我把云朵间的空白移过去'。」

### 1.3 微软已经用同样的思路做了，并且被判定"解错了题"

**事实**｜MakeUseOf 实测 Windows Click to Do 后的结论，几乎是在替我们写需求文档：

> 它需要**大得多的上下文感知**……更重要的是，**跨应用动作会非常有用，比如「把这份 PDF 的这一段放进 Slack」「把这句话发到 Outlook」**。
> 现在它更像 Don't-Click 而不是 Click to Do。
> — https://www.makeuseof.com/microsoft-push-windows-11-feature-solves-wrong-problem/

失败原因很具体：只能总结屏幕上可见的那点内容、只能用 NPU 上的 Phi Silica 小模型、每次都要等加载打断专注、不同机器上功能还不一致。

**推断**：微软/谷歌的结构性天花板不是技术，是**它们必须把你锁进自家模型**。Click to Do 只能交给 Copilot，AI Pointer 只能交给 Gemini。它们不会把上下文交给你自己付费的 Claude Code / Codex。**这是它们不会跨过来的一条线，也就是我们的活路。**

### 1.4 代码场景已经关闭，不要进去

**事实**｜r/vibecoding「大家还在往 AI 对话框里复制粘贴文件吗？」86 条回复，最高赞是一句话：「Just use Claude Code.」次高：「立刻换 CLI。IMMEDIATELY。」

**推断**：给 AI 喂**代码仓库**上下文——这件事已经被 Claude Code / Codex 彻底解决了。我们如果把宣传落在"帮 AI 拿上下文"，会被一句话打死。
我们真正的领地是**代码之外、GUI-only、没有 MCP server 的那部分世界**：微信/飞书聊天、PDF 扫描件、报错弹窗、设计稿、视频帧、老旧的 Windows 业务系统、别人发来的截图。
MCP 服务的是**愿意配合的应用**；我们服务的是**不配合的应用**。这两句话应该刻在产品定位上。

### 1.5 什么样的 AI 工作流会活下来

**事实**｜Every《Why Some AI Workflows Stick—And Others Don't》，作者对自己废弃的一堆 AI 工作流做尸检，归纳出**四个死因**：

1. 我忘了它的存在
2. 它没跑起来（不可靠）
3. 输出需要太多善后
4. 它解决的不是一个反复出现的问题

活下来的两个条件：**在你已经在做的事情内部与你相遇**；**立刻回报**（行为学研究：即时奖励比延迟奖励更能预测坚持）。
— https://every.to/working-overtime/why-some-ai-workflows-stick-and-others-don-t

**推断（这条是我们最大的结构性优势）**：死因 #1「我忘了它的存在」是所有 chat 型 AI 产品的头号杀手，因为它们要求你**主动去一个地方**。
Magic Pointer 的触发器是**你手里已经握着的那只鼠标，在摩擦正在发生的那一秒**。它在结构上不可能被忘记。
→ **推论（必须当成铁律）：永远不要要求用户"打开 Magic Pointer"。任何需要先打开主界面的功能，都是在把我们唯一的结构性优势扔掉。**

### 1.6 护城河在"操作知识层"，而且它必须是自然语言

**事实**｜2026 年 4 月同一周，GitHub Trending 前列被五个"如何更好使用 coding agent"的仓库占满，合计 20 万+ star：obra/superpowers 143,712★、luongnv89/claude-howto 24,002★、oh-my-codex 19,938★（当周全站增速第二）、andrej-karpathy-skills 10,441★——**最后这个的全部内容就是一个 CLAUDE.md 文件**。
结论：**CLAUDE.md 这种"自然语言配置"本身成了产品品类**。相比 `.vimrc`/`.emacs` 需要先学配置语言，自然语言配置的**消费摩擦接近于零**，所以传播速度不是一个量级。
— https://crowdy.dev/en/2026/04/10/claude-code-meta-ecosystem-moat/

**推断**：用户想要的"第三方插件生态"，正确形态**不是 SDK、不是 API、不是要人写 Python**，而是**一个文件夹 + 一个 Markdown**。谁都能写、谁都能读、复制即用、不需要构建。
这直接判了我们现在 `app/fabric/catalog.py` 死刑（见 §3.1）。

## 2. 战略定位：把分工反过来

### 2.1 核心命题

| | 别人（computer-use / GUI agent） | Magic Pointer |
|---|---|---|
| 谁负责"指出哪个" | 模型（截图 → 视觉 grounding → 猜坐标） | **人手**（圈/划，200ms） |
| 定位成本 | 15,000+ tokens/次，秒级延迟 | **0 token，0 延迟** |
| 定位准确率 | OSWorld 38% | **100%**（人不会指错自己看着的东西） |
| 上传什么 | 整屏，且往往持续 | **只上传你圈的那一块，且只在你圈的那一刻** |
| 谁负责推理执行 | 模型 | 模型（用户自己已付费的那个） |

**这一栏对齐了三个 HN 最大反对意见**：贵（0 token 定位）、慢（无视觉往返）、不信任（不常连、不整屏）。

### 2.2 我们不做什么（战略边界，比做什么更重要）

- **不做通用 computer-use。** 我们不替用户点按钮、不做 OSWorld。执行交给结构化接口（UIA/COM/DOM/深链）或交给用户的 agent。
- **不进代码上下文赛道。** Claude Code 已经赢了。
- **不做常驻录屏/Recall 型记忆。** HN 对 Recall 的敌意是明确的，且这与我们的隐私叙事直接冲突。要记忆，记的是**你圈过什么、你要它做什么**，不是你看过什么。
- **不把用户锁进某个模型。** 这是我们相对 Google/Microsoft 的唯一结构性差异，不能自己放弃。

### 2.3 主战场（唯一不可替代的领地）

> **Ctrl+C 复制不了的东西。**

这是一条极其锋利的边界。凡是 Ctrl+C 能搞定的，我们大概率更慢；凡是 Ctrl+C 搞不定的，目前**全世界只有"人工重打"这一个方案**。

清单（都是每天发生、且用户从未把它当成"问题"的事）：

| 场景 | 用户现在怎么做 | 频率 |
|---|---|---|
| 图片/扫描 PDF 里的文字 | 手打 | 每天 |
| **报错弹窗里的错误信息** | 截图发群里问 | 每周多次 |
| 微信/飞书里别人发的表格截图 | 对着屏幕手抄进 Excel | 每周 |
| 视频/网课里的公式、代码 | 暂停手抄 | 学生每天 |
| **想让 agent 处理某个文件，得先找到路径** | 翻文件夹 → 右键 → 复制路径 | 每天 |
| 后台系统里不可选中的表格 | 手抄 | 财务/运营每天 |
| 图片里的地址/单号/电话 | 手打 | 每天 |

**赌注**：这些场景用户不觉得是痛点，因为他们从没见过替代方案——正如用户所说的"糊弄过去了"。**"眼前一亮"必须发生在这里，而不是发生在"我能指挥 AI 干活了"。**
后者是叙事，前者是留存。

## 3. 底层复盘：够不够，好不好

### 3.1 现在的底座（诚实盘点）

**已经很好、可以往上盖楼的**：

- 感知级联：UIA/DOM/COM → OCR → 视觉，**结构化优先于截图**（8/2 修的那个洞很关键）
- `InteractionEpisode`：THIS/THAT/THESE/HERE 多对象绑定
- `ContextPacketBuilder`（710 行）+ `build_agent_prompt` + `agent_context_handoff` + `hooks.py` —— **这就是用户说的"母功能"，它已经存在且成型**
- 权限 fail-closed、model_plan 严格校验、target_lease、provenance、audit
- 跨应用连续圈选 Hook（昨晚已 GREEN）——这是把"多源"变成可能的物理前提

**不够的，按严重程度排**：

| # | 缺口 | 为什么致命 | 对应证据 |
|---|---|---|---|
| **A1** | **Recipe 是 `catalog.py` 里硬编码的 Python 元组（81 行、30 条）** | 第三方插件在结构上不可能存在。用户想要的生态在这里被物理封死 | §1.6 自然语言配置成为品类 |
| **A2** | **没有记忆层** | 同一件事做 20 次，产品学不到任何东西。每次都是冷启动 → 无累积、无锁定 | Every 死因 #4；「AI memory 是下一个 lock-in」 |
| **A3** | **没有"零模型快路径"的一等公民地位** | 现在一切都过 router→plan。取一段文字这种事应该 **0 次模型调用、<200ms**。否则输给 Ctrl+C 和手打 | HN「5 秒改一个数字」 |
| **A4** | **语音是门槛而非加速器** | 一大批用户（开放办公室/咖啡馆/不想说话）会在第一分钟流失。且我们已知 p50 4.3s | HN 6 条独立反对 |
| **A5** | **没有摩擦触发层** | 死因 #1「我忘了它的存在」的唯一解药。用户提到的 hook 正是用在这里，但目前 hook 只用于 agent prompt 注入 | Every 死因 #1 |
| A6 | 微信媒体物化未完成（RED 中） | 中文市场第一场景 | QClaw 也没做到 |
| A7 | 无成本/延迟预算 | 长会话必炸上下文；无法向用户承诺"这次要花多少" | OpenSRE context_budget |

### 3.2 三个母功能（其余全是延伸）

用户问"主要功能形态到底是什么"。答案是三个，且它们共用同一个底座。

```
                    Episode（会话）
                        │
        Object（对象）── Evidence（证据）── Contract（契约）
                        │
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
    ① 取 Extract    ② 交 Handoff    ③ 改 Act
```

**① 取（Extract）— 留存引擎**
把屏幕上"看得见但拿不到"的东西变成可用数据：文本、表格、公式、**文件绝对路径**、图片、错误信息。
特征：高频、即时回报、**大部分可 0 次模型调用完成**、失败也无害。
→ 这一层负责"用户每天打开它"。Every 说的"立刻回报"就靠它。

**② 交（Handoff）— 价值上限**
多源上下文（跨应用、跨时间）聚合 → 结构化 Prompt → 气泡内可编辑 → 投递给用户自己在跑的 agent 会话。
昨天 `d9f92b1` 已经落地了这条链的主干。
→ 这一层负责"用户愿意付费"。也是 Google/Microsoft 结构上不会做的那件事。

**③ 改（Act）— 信任**
原位写回 + 读回验证 + 撤销。风险最高，必须 fail-closed。
→ 这一层负责"用户敢把它留在系统里"。Marvis 的"频繁硬垂询"是反面教材：**确认要少而准，不是多而烦**。

30 个 Recipe、未来所有第三方插件，都只是这三个母功能的参数化。**任何新想法先问：它是取、交、还是改？如果三个都不是，大概率不该做。**

### 3.3 底层要补的四件事（按顺序）

**第一件：把 Recipe 从代码变成数据（解 A1）**

目标形态——任何人建一个文件夹就是一个插件，不需要构建、不需要写 Python：

```
recipes/
  copy-error-dialog/
    recipe.md          # 自然语言：什么时候用、做什么、怎么验证（≈CLAUDE.md）
    manifest.toml      # 结构化：输入 kind、输出 kind、风险等级、需要的权限
```

- `catalog.py` 退化为**加载器 + 内置 recipe 的默认目录**
- 权限必须仍由本地策略裁决，插件只能**申请**不能**授予**（沿用 model_plan 的 fail-closed）
- 内置 30 条先全部迁成文件，自己吃自己的狗粮——迁不动就说明格式不对

**第二件：给"取"开一条零模型快路径（解 A3）**

一条与 router/plan **完全并行**的确定性通道：圈选 → 结构化读取/OCR → 剪贴板/文件。目标 **<200ms、0 次模型调用、离线可用**。
只有它先于模型返回，我们才在"比 Ctrl+C 快"这件事上站得住。

**第三件：让语音变成加速器（解 A4）**

- 气泡必须**全程零语音可用**：圈完直接出候选动作（因为**圈选本身已经携带了大部分意图**——圈一张表 = 提取表格，圈一段报错 = 复制/搜索）
- 打字输入与语音**同等一等公民**，且默认焦点在输入框（HN 明确要「Spotlight 那样的弹窗」）
- 语音降级为"我懒得打字时的快捷方式"，它的 4.3s 延迟就不再是主路径阻塞

**第四件：摩擦触发层（解 A5，这是"眼前一亮"的交付通道）**

现有 `WH_MOUSE_LL` + `SetWinEventHook` 已经能看到这些信号，成本几乎为零：

| 检测到的摩擦信号 | 一次性提示 |
|---|---|
| 连续两次截图 | 「要直接把里面的文字取出来吗？」 |
| 在两个窗口间来回切 3 次以上 | 「要把这两边的内容合成一条给 agent 吗？」 |
| **在输入框手打的内容，与屏幕上已存在的文本高度重合** | 「这段屏幕上已经有了，要直接取吗？」← 最强的一击 |
| 反复打开同一个文件夹找文件 | 「圈一下文件图标就能拿到路径」 |

铁律：**同一提示一生只出现一次，可永久关闭，绝不打断输入焦点。** 越过这条线就是 Clippy，会直接毁掉产品。

| `D:/AI_Agents/pi` | Extension SDK 底座（已有 `integrations/pi/`） | 插件宿主参考 |
| `external/opensre` | `context_budget`（解 A7）、可逆脱敏（解隐私叙事） | 只借模式 |

**"AI 指着屏幕教你"（clicky 的核心体验、XDA 说"今年试过最有用的东西"）值得单独立项**：它属于"取"的反向——不是把屏幕给 AI，是把 AI 的答案放回屏幕。而且它是**唯一一个语音真正合理的场景**（你手在操作软件，说话是自然的旁路）。

## 5. 我对自己这套结论的反驳（battle）

诚实列出这套战略可能怎么死：

1. **「Ctrl+C 复制不了的东西」市场是不是太小？**
   反驳：不小，但**用户不会用这个词搜索**。他们不会搜"OCR 工具"，他们只是在手打。所以获客靠**演示**而非搜索——一个 15 秒的"圈住报错弹窗 → 文字到手"视频，比任何功能列表有效。这是营销问题不是市场问题。

2. **零模型快路径做出来，我们是不是就退化成一个 OCR 工具？**
   这是最真实的风险。答案：**"取"是入口不是产品**。留存靠取，付费靠交（②）。定价必须让"取"永久免费——它是获客成本，不是收入。

3. **第三方插件生态，早期根本没人写。**
   属实。所以第一件事的真正目的**不是**招募第三方，而是**让我们自己迭代 recipe 不用发版**。生态是副产品。如果一年后没人写插件，这个改造依然值回票价。

4. **摩擦触发层做砸了就是 Clippy。**
   最高风险项。缓解：默认全关，只在用户完成过一次成功操作后才允许出现第一条；每条一生一次；有一个"永不再提示"的全局开关且它必须真的生效。

5. **用户根本记不住要晃鼠标。**
   这是 §1.5 死因 #1 的具体形态。晃动是个**需要学习的新动作**，它其实违背了"零召回成本"。
   → **需要一个不用学的备用触发**（如侧键、或选中文本后浮现的极小把手）。这一条我还没有结论，建议上线前用真人测。

## 6. 建议的推进顺序

不是路线图，是**依赖顺序**：

```
0. 收掉昨天的断点（微信媒体 RED → GREEN）        ← 不收掉就是技术债
1. 零模型快路径（"取"）                          ← 立刻能感知的价值，且不依赖任何其他改造
2. 语音降级为加速器 / 打字一等公民               ← 与 1 同批，改的是同一个气泡
3. Recipe 数据化 + 插件加载器                    ← 底座改造，之后所有功能不用发版
4. 记忆层（记"你圈过什么、要它做什么"）           ← 依赖 3 的数据格式
5. 摩擦触发层                                     ← 依赖 1（得先有东西可推荐）
6. "AI 指着屏幕教你"（收编 clacky tour）          ← 独立，可并行
```

**每一项交付前必须回答**：它是取/交/改中的哪一个？它在 200ms 内给出第一个反馈了吗？用户不说话能用吗？

## 0. 定位（执行者每轮开工前读一遍）

Agent 太多了，但"Agent 能做什么"和"用户此刻在屏幕上想要什么"之间有一道真实的 gap：用户得截图、复制、切窗口、组织语言、把东西**搬**给 AI，再把结果**搬**回来。**我们就是这道 gap 的填补者**：屏幕上任何东西（能 Ctrl+C 的、不能 Ctrl+C 的、图、元件、窗口）与任何智能（模型 API、本地模型、用户已装的 codex/claude CLI、MCP 生态）之间的**通用衔接层**。三个母动作不变：**取**（拿下来）、**问改**（就地处理）、**交**（递给别的智能体）。

**缝合怪战略，光明正大**：MIT/宽松许可的直接抄代码进来；GPL/BSL 的读懂思想后用自己的方式实现——一行行都是我们自己写的，这就是我们做的。来源清单见 §7。

## 1. 三条执行纪律（用户定的，覆盖一切默认行为）

1. **不死磕**。任何单点（尤其是性能）做到"可用"就停：记一条 TODO 进 AGENT.md（写清当前数字、剩余空间、下一步思路），立刻切下一项。例：延迟做到百毫秒量级就走人，别为最后 50ms 耗三天。
2. **持续提交，没有"大版本"**。每个功能做完（真机验过）就提交，主分支永远可跑。发布是水到渠成的事，不是里程碑。
3. **兜底智能，永不说"不支持"**。用户任何输入都必须有像样的结果。规则覆盖的走快路径，规则外的落到通用模型路径（§3 的 L2）。"列出来的功能能做、稍有偏差就死"是本项目最不可接受的状态。

## 3. Phase 1a — 智能路由重做（消灭"死板"，2 天）

**三层路由，落点是把 `selection_bridge.py` 的 `main()` 重构成单一 `route(command, context)` 入口：**

- **L0 确定性快路径**（零模型，目标 <300ms）：十几个高频确定意图（复制、OCR、截图、翻译到默认语言、收藏……）关键词直接命中，直接执行。现有 `_reference_label_response` 等链路归入此层。
- **L1 意图分类**（一次轻量模型调用，<1.5s）：`命令 + 对象摘要` → 选 recipe + 抽参数。低置信或分类失败**不报错**，落到 L2。
- **L2 通用对话兜底**：把全部 recipe 作为 **tools（function calling）**交给模型自由组合；组合不出来就纯文本回答。用户说"框起来""帮我把这段变成小红书文案""这图里第三列加起来是多少"——不管有没有对应 recipe，**永远有一个尽力而为的答案**。`agent.handoff` 降级为 L2 里的一个普通 tool，只在"交给 codex / 在仓库里改"类显式意图时被选中。
- **长尾学习**：L2 里同一模式出现 ≥3 次，提示"存为自定义指令？"→ 进 prompt library（§5 能力区），下次走 L0。

**配套地基（同一改动里做掉）**：`catalog.py` 的硬编码 Python 元组 → **JSON manifest + 加载器**（Flow.Launcher 范式）。每条 recipe 一个声明文件（id、人话名、触发词、风险、参数 schema、provider）。这是 §6 批次 C 插件生态的地基，现在打，后面白捡。

## 4. Phase 1b — 交互形态 v3（对齐并超越 Google demo，1 周）

### 4.1 流式回合，替代"画完→统一回车→一条消息"

现状的死板根源：所有笔画攒着，最后一次性提交。改成**一条时间戳流**：

- 指针武装期贯穿整句话（一次唤醒说完整件事，不是一笔一会话）；
- 每一笔落笔 **250ms 内**出反馈：目标高亮 + 一个 chip 插进输入流（打字打到"把"时划一笔，输入框当场变成 `把 [①1 lb Spaghetti]`；语音的 ASR partial 流进同一个框）；
- 词与笔画按时间戳绑定：`[(笔画₁,t₁),(词,t),(笔画₂,t₂)…]`，代词绑定到它前面最近的一笔——AGENT.md 已确认 `InteractionEpisode` 的多对象绑定都在，**缺的只是记账，不是 AI**；
- 静默 1.2s 或回车结束回合。提交前每个 chip 可删可改——这是我们比 Google demo 强的三点之一（另两点：静音可用、选中的东西一直看得见）。

### 4.2 点选模式（Everywhere 那个"X 帖子点一下四周亮起来"的效果)

- **悬停/点击 = 整元素高亮**：UIA `ElementFromPoint` 拿元件 rect → `sweep_band` 光带（两样都已存在，缺的是"点选"这个触发入口）；**划线 = 子元素**。两种粒度并存，对应 Google demo 的 hover=容器/stroke=子元素语义。
- 零元件窗口（微信等）→ OmniParser 视觉框选兜底（§6 批次 C-12），同一个高亮 UI，不同的 rect 来源。

### 4.3 选区拉伸把手（用户点名的功能）

选中 8 句话里的第 3–4 句 → 快捷键/气泡按钮唤出**上下两个拉伸把手** → 往下拖三行的距离，实时显示"目标 5 行" → 松手，模型按目标长度扩写；往上拖同理压缩。Word 走 COM 原位替换（已有），其余应用走「填入」通道（已有）。**同一手势复用到答案卡**：拖卡片下缘 = 更详细/更简略（shapeof.ai 的 Expand 模式，AGENT.md 里用户早就要过）。

### 4.4 视觉与动效基线（"高级感"从这里来）

- **先定稿设计 token，结束 `stage.css` 石墨黑/浅蓝白分叉**：气泡与浮层用浅色玻璃（现状），设置中心与面板用深色 mica（对齐用户展示的 ChatGPT 桌面端），一套 accent 色贯穿，可在外观页改（§5）。
- 动效沿用既有规范（ease-out-quint 120–350ms、只动 transform/opacity、`prefers-reduced-motion` 全关），补齐：chip 入流、元素高亮呼吸、把手拉伸的橡皮筋感、结果卡骨架屏。
- 图标不再从表情库随便捡：能力库图标用一套线性图标（lucide，MIT），和 chip/徽章共用视觉语言。

## 9. 给执行者的红线（沿用 + 新增，违反任何一条即返工）

1. 不开子 agent（用户成本约束，明确指示过）。
2. 过程汇报用中文、说人话，file:line 留给文档。
3. 不假报成功：读不回来就说读不回来；`verified=False` 过不了成功门是特性。
4. 内部数据（lease/fingerprint/错误码/Context Packet）永不进给人看的气泡。
5. 性能对比必须交替 A/B 测量（这台机器绝对耗时漂移 200ms，顺序对比无效——已踩过坑）。
6. 真机冒烟不可省：自动测试全绿 + 真机全挂已经发生过一次。
7. 每功能一提交；契约变更（如 requestMode 这种）必须同时落一个测试钉子。
8. 优化超预算 → 记 TODO + 换任务（纪律 1 的强制形式）。

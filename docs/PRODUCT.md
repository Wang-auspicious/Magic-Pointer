# 产品定位

> 改方向前读这一份。证据分级：**事实**＝有链接可核；**推断**＝基于事实的判断；**赌注**＝没有证据、只能靠上线验证。

## 一句话

**所有人都在让 AI 去用鼠标。我们让鼠标去喂 AI。**

Magic Pointer 是屏幕上任何东西（能 Ctrl+C 的、不能 Ctrl+C 的、图、元件、窗口）与任何智能（模型 API、本地模型、用户已装的 codex/claude CLI、MCP 生态）之间的**通用衔接层**。默认不可见：晃动鼠标唤醒 → 划线指向 → 打字或说话 → 读对目标、给出回答或执行。

**不是**聊天壳、不是截图问答器、不要求用户先打开我们。

## 三个母动作

其余全是这三个的参数化。**任何新想法先问：它是取、问改、还是交？三个都不是，大概率不该做。**

| | 是什么 | 负责什么 |
|---|---|---|
| **取** Extract | 把"看得见但拿不到"的变成可用数据：文本、表格、公式、文件绝对路径、报错信息 | 用户每天打开它。高频、即时回报、大部分可 0 次模型调用 |
| **问改** Act | 就地提问、改写、原位写回 + 读回验证 + 撤销 | 用户敢把它留在系统里。风险最高，必须 fail-closed |
| **交** Handoff | 多源上下文聚合 → 结构化 prompt → 气泡内可编辑 → 投递给用户自己在跑的 agent | 用户愿意付费。也是 Google/Microsoft 结构上不会做的那件事 |

## 主战场：Ctrl+C 复制不了的东西

凡是 Ctrl+C 能搞定的，我们大概率更慢；凡是 Ctrl+C 搞不定的，目前全世界只有"人工重打"一个方案。

图片/扫描 PDF 里的文字、报错弹窗里的错误信息、微信里别人发的表格截图、视频里的公式和代码、想让 agent 处理某个文件却得先翻文件夹找路径、后台系统里不可选中的表格、图片里的地址单号电话。

**赌注**：用户不觉得这些是痛点，因为他们没见过替代方案——他们只是在手打。所以获客靠**演示**而非搜索：一个 15 秒的"圈住报错弹窗 → 文字到手"视频比任何功能列表有效。

## 战略边界（比做什么更重要）

- **不做通用 computer-use。** 不替用户点按钮、不做 OSWorld。执行交给结构化接口或交给用户的 agent。
- **不进代码上下文赛道。** Claude Code 已经赢了。r/vibecoding 那条帖子 86 条回复，最高赞就一句「Just use Claude Code」。我们的领地是**代码之外、GUI-only、没有 MCP server 的那部分世界**。MCP 服务愿意配合的应用，我们服务不配合的应用。
- **不做常驻录屏/Recall 型记忆。** 要记忆，记的是**你圈过什么、你要它做什么**，不是你看过什么。
- **不把用户锁进某个模型。** 这是相对 Google/Microsoft 唯一的结构性差异，不能自己放弃。
- **永远不要要求用户"打开 Magic Pointer"。** 任何需要先打开主界面的功能，都是在把唯一的结构性优势扔掉。

## 为什么这个分工是对的

|  | 别人（computer-use / GUI agent） | 我们 |
|---|---|---|
| 谁负责"指出哪个" | 模型：截图 → 视觉 grounding → 猜坐标 | **人手**，划一笔 200ms |
| 定位成本 | 15,000+ token/次，秒级延迟 | **0 token，0 延迟** |
| 定位准确率 | OSWorld 最强 agent 38%（人类 72%） | **100%**，人不会指错自己看着的东西 |
| 上传什么 | 整屏，且往往持续 | 只上传你圈的那一块，只在你圈的那一刻 |

这一栏同时对齐了 HN 上最大的三个反对意见：贵、慢、不信任。

**事实**｜腾讯 QClaw 实测：权限给全，能打开微信、能点开搜索框，**就是发不出一个文件**。36氪的定性最关键：「Agent 在用人类的界面，做机器的事情……一旦进入执行阶段，它不知道当前界面是否真的打开，不知道点击是否生效。所有动作本质上还是猜一个最可能的下一步。」
**事实**｜Windows Click to Do 被判定"解错了题"：只能总结屏幕上可见的那点内容、只能用 NPU 上的小模型、每次都要等加载。**推断**：微软/谷歌的天花板不是技术，是它们必须把你锁进自家模型——Click to Do 只能交给 Copilot，AI Pointer 只能交给 Gemini。它们不会把上下文交给你自己付费的 Claude Code。**这是它们不会跨过来的一条线。**

## 用户会怎么把它用废

Every 对自己废弃的 AI 工作流做尸检，四个死因：① 我忘了它的存在 ② 它没跑起来 ③ 输出需要太多善后 ④ 它解决的不是反复出现的问题。活下来的两个条件：在你已经在做的事情内部与你相遇；立刻回报。

死因 ① 是所有 chat 型 AI 产品的头号杀手。我们的触发器是**你手里已经握着的那只鼠标，在摩擦正在发生的那一秒**，结构上不可能被忘记——**但晃动是个需要学习的新动作，它其实违背了"零召回成本"**。需要一个不用学的备用触发（侧键、或选中文本后浮现的极小把手）。这条还没有结论，上线前要用真人测。

## 语音的位置

语音是**加速方式，不是主路径**。`default_input_mode` 默认 `text`。

HN 上语音是重复出现的最大反对意见，至少 6 条独立高赞：「我看到那个 demo 需要麦克风，直接关掉了。如果做成 Spotlight 那样打字的弹窗，办公室就能用」「我不想跟电脑说话。是的我很确定。问题不是它不够好，是我不想要」「99% 的办公室是开放式的」。

所以：气泡必须**全程零语音可用**，打字与语音同等一等公民，默认焦点在输入框。唯一语音真正合理的场景是"AI 指着屏幕教你"——你手在操作软件，说话是自然的旁路。

## 竞品

| 产品 | 地位 | 我们拿什么 |
|---|---|---|
| **Google AI Pointer** | 完整对标目标 | 产品形态、划线视觉、指代交互范式。**注意 `demo/recordings/演示7\|8\|9.webm` 是无声矢量动画（max_volume −91 dB），不是录屏，别当可运行实现对标**——抄它的时间线语法，不要抄它的性能数字 |
| **Everywhere**（BSL 1.1，禁竞用） | 最直接的竞品，比我们早一年，6207 star | **只读思路，一行不复制**。它是快捷键→聊天窗口→agent 工具循环，没有语音、没有手势圈选、没有原位改写。它框得又快又准（常驻原生热路径 + 真实 UIA rect + WGC/D3D 帧 + 缓存），但**框得准不等于上下文策略对**：录屏里用户只圈一个投票小框，它照样把大范围页面交给模型，12 万 token 等近一分钟 |

| UFO²、OmniParser、UI-TARS | 借鉴模式 | 复用适配器思路，不搬整套架构 |

## 这套结论可能怎么死

1. **「Ctrl+C 复制不了的东西」市场太小？** 不小，但用户不会用这个词搜索。营销问题不是市场问题。
2. **零模型快路径做出来会不会退化成 OCR 工具？** 最真实的风险。答案：**"取"是入口不是产品**，留存靠取、付费靠交。定价必须让"取"永久免费。
3. **第三方插件早期根本没人写。** 属实。所以插件化的真正目的不是招募第三方，而是**让我们自己迭代 recipe 不用发版**。生态是副产品。
4. **摩擦触发层做砸了就是 Clippy。** 最高风险项。缓解：默认全关、同一提示一生只出现一次、"永不再提示"开关必须真的生效。

# Jev 免费候选接口与最小对照

官方接口依据：[OpenCode Zen Jev](https://opencode.ai/docs/zen/#jev)。使用 `https://opencode.ai/zen/v1/systemone` 和固定 `jev-1.13-free`，不自动换付费模型。本机现有 OpenCode API 认证已实测可用；认证仅在内存读取，不复制进仓库、报告或模型提示词。

## 实测与决定

完整六例输出在 [2026-09-20-jev-comparison.json](2026-09-20-jev-comparison.json)，复跑入口为 `python scripts/benchmark_jev_targets.py`。输入均是合成控件文字，不含用户桌面、文件或会话。对照的是同一组候选的本地精确名称匹配、Jev结构化选择、当前订阅主模型 `deepseek-v4.1-flash`；不是完整视觉操作成功率。

| 场景 | 本地精确名称 | Jev辅助接口 | 用时 |
|---|---|---|---:|
| Save 精确名称 | 正确命中 | 直接使用本地结果，零远程调用 | <1 ms |
| 留邮件但移出收件箱 | 无法判定 | Archive，正确 | 1891 ms（本次冷连接） |
| 不应用编辑而关闭对话框 | 无法判定 | Discard changes，正确 | 625 ms |
| 只打印当前工作表 | 无法判定 | Print active sheets，正确 | 734 ms |
| 中文“留着以后看，不删除” | 无法判定 | 置信度0.66，退回候选 | 703 ms |
| 页面不存在的暗色模式 | 无法判定 | none，正确拒绝猜测 | 594 ms |

Jev返回的四个具体ref全部正确（含一个本地命中）；一例正确拒绝不存在的目标，一例中文语义选择低置信度而放弃。主模型一次批量回答六例全部正确；此次6031 ms，首次连接预算实验中的同一批次为3766 ms。批量主模型耗时与单次Jev耗时不等同于端到端加速倍率，因此不声称整体快了几倍。

更早的最简单Save请求冷调用约6017 ms，随后同连接579/594 ms，接口费用字段均为0。初版把连接阶段限制为1秒会频繁ConnectTimeout；最终保留3秒后台连接上限，但工具前台等待仍严格900 ms。冷请求到期立即返回现有候选，后台只完成这次已发出的请求并复用连接，不排队追加请求。

根据这些结果，接入 `choose_ui_target` 作为模型可发现的只读工具。先查完整原始UIA节点，唯一精确名称直接命中；语义歧义才调用Jev。超过64个候选要求调用方显式缩小candidate_refs，不静默截断原始候选池。暖请求通常能在900 ms预算内完成；低置信度、未知候选、网络错误、取消和繁忙均退回现有候选。等待期间每25 ms检查取消，最多一个后台请求。

已有 `search_ui` 同时接入这条接口：非空文字的本地完整匹配为零时，在同一次工具调用里附带 `suggested_target`，保留原literal matches，不要求主模型为了尝试Jev多走一轮工具调用。存在本地匹配时不会调用Jev。单元回归默认禁用本机Jev认证，避免普通测试误联网。

HTTP客户端按需在受等待预算约束的后台请求中创建；本地精确匹配不初始化HTTP/TLS。这样首次调用的客户端初始化也不会额外阻塞调用方，后续请求继续复用同一连接池。两项新增回归先复现了初始化发生在预算之外的问题，修后Jev独立回归共8项通过。

Jev输出只有现有state_id下的ref建议。实际点击/输入仍通过原有租约、目标重验证、权限与结果读回；Jev不生成坐标、授予权限或自行发送/删除。它不替代视觉模型或主Runtime，不用于压缩历史，也不增加常驻截图或空闲模型请求。

## 验证边界

单元测试覆盖免费模型/固定地址、明确名称零调用、完整第150个原始候选、未知ref、低置信度、取消、严格等待上限和繁忙退回。组合注册测试确认工具进入真实Harness inventory。免费资格是供应商当前的限时政策；若供应商停止提供免费ID，现有错误退回路径生效，不会切到付费版。

# 2026-09-20 Computer Use 审计修复闭环

范围：`audit-2026-09-20-computer-use.md` 中 CU01–CU27。27 项均已完成生产修复及相关行为回归；本文件不把替身/协议测试等同于真实应用验收。生产源码已冻结，由主任务统一做全量 Python、Node、typecheck、版本更新、sync 和 Git 提交。

采用 test-first：先运行新增回归并观察预期失败，再修改生产文件。测试驱动、截图、DOM、OCR、视觉请求均使用替身；跨进程输入所有权测试真实创建 Windows 内核 mutex，但不执行鼠标、键盘或窗口操作。

## 尚未宣称的验收与测试失误

- 没有启动 Electron/Office/聊天/浏览器做真实点击、粘贴、拖拽或发送，也没有把截图/视觉替身等同于 WGC、PrintWindow 或 TextPattern 在所有应用已验收。Focus、横向滚动、剪贴板输入、原生 TextPattern、真实窗口被遮挡、PDF 冻结图坐标、真实提供者卡死和真实 HTTP Stop 延迟仍需主任务区分安装验收与协议回归。
- 唯一真实 OS 互斥验证是独立 Python 进程的 Windows named mutex，未触发用户应用操作。隔离 worker deadline 验证用 `sleep(30)` 子进程，非真实挂死 Office。
- CU12 是已知控件和明确操作的确定性分类，不是通用图像语义判定。没有可辨名称的控件由明确 intent 声明实际效果；运行时仍消费分类并检查授权。未知会话身份不能沿用旧 sourceId。
- 初批修改 multiline Type 后，旧测试只替换 SendInput，遗漏 clipboard seam，曾实际把 Windows 剪贴板改成测试字符串 `A\r\n\tB`；随后因 fake driver 缺 `_user32` 失败。没有真实键盘/鼠标输入或发送。旧测试已同时替换 `pyperclip.copy` 与按键接口，新回归替换完整 paste seam。原剪贴板内容未知，未声称恢复。
- 本文件不宣称最终整仓全量验证、安装包 sync、版本更新或发布完成；这些由主任务汇总执行。

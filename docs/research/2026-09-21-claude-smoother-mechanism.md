# Claude Desktop 2.110.0.0：文本平滑器（"流动性"）机制取证

取证日期：2026-09-21。接续 `2026-09-20-claude-streaming-reference.md`（那份查的是**提交节奏** 33/100/200ms 与思考/子 Agent 渲染）。本次专门查用户问的"流式输出为什么看起来在流动"。范围为本机已安装 Windows 包的静态资源；没有启动 Claude，没有访问账号、登录状态或网络，没有改动 Magic Pointer 生产代码或测试。

## 结论

**机制存在，而且比"打字机"讲究得多：一个以字符数为状态量的、带势垒约束的阻尼跟随器。** 它把"模型到达了多少字"和"屏幕显示到第几个字"彻底分开：显示位置以 60fps 独立演化，受两个硬边界夹住——上界是已经到达的字符数（绝不显示还没到的内容），下界是"已经迟到"的字符数（落后太多时必须追）。速度自身还是一阶惯性（EMA α=0.99）。

**但在本机这个版本里，Claude Code 这条流是把它关掉的。** `dont_smooth=!0`，导出的诊断里写着 `passThrough:!0, intervalMs:33`。所以你在 Claude Code 对话里看到的"流动感"不来自这个平滑器，而来自上一份取证的 33ms 提交节奏 + 首段立即提交 + 结束事件强制冲刷。平滑器是同一份基类里的另一条路径。

## 状态量与常量

```
alpha = 0.99      速度 EMA 系数（重惯性，每步只吃 1% 新信息）
gamma = 1e-5      弹簧刚度（极小）
v     = 100       初始速度（字符/秒）
x     = 0         当前显示位置（字符，浮点）
t     = 0         上一步的时间（秒）
arrivals = [[-9999, 0]]      历史 [(秒, 累计字符数)]，带哨兵头
cg = 1000/60 = 16.67ms       可见时的步长
ug = 100ms                   面板不活跃时的步长
lg = 200ms                   文档隐藏时的轮询步长
```

`arrivals` 是这套东西的关键：它记的是**到达曲线**，不只是当前总量。后面算下界要用到"多久之前到的"。

## 每步怎么算

`_get_smoothed_completion()`：

1. 已经追平（`x >= 总长`）就直接按全长切片返回，并维护一个"内容没变"标志，避免下游重复提交。
2. `t = (now - start)/1000`，`n = max(t - 上次t, 1e-6)`。
3. 上界 `r = 最后到达的字符数 + (模型已完成 ? 100 : 0)`——写完时额外放宽 100 字，让收尾也顺完。
4. 下界 `s = max(arrivals 里时间 < (0.9t - 0.3) 的最后一个到达量, 模型已完成 ? 末值 : 停止时字符数)`。`0.9t - 0.3` 是一条**比真实时间滞后约 10% 再减 0.3 秒**的线：晚到这么久的字，就不允许再拖了。
5. 解方程求新位置 `c ∈ (s, r)`：

```
f(e) = 2γ·(1/n)·((e - x)/n - v)  -  1/(e - s)  +  1/(r - e)  = 0
```

- 第一项是阻尼器：把"位置误差除以步长"和当前速度 `v` 对齐。
- `-1/(e-s)`：`e` 逼近下界时趋于 −∞，把解往上顶。
- `+1/(r-e)`：`e` 逼近上界时趋于 +∞，把解往下压。

也就是位置被**夹在已到达与已迟到之间**，靠近哪边就被哪边推开。`γ=1e-5` 让弹簧项非常软，主要靠势垒定形。

6. `v = α·v + (1-α)·((c - x)/n)`——只在没有迟到内容（`下界 <= x`）时更新速度，即**落后追赶期间不改速度基准**。
7. `x = max(c, x)`：**位置单调，绝不回退**。
8. 每一步把 `{t, x, v, min_chars, max_chars}` 推进 `stats`——他们是把这套东西当控制回路在示波器上看的。
9. 返回 `sg(blocks, blocksList, x)`：按浮点位置切块。

`ag` 是二分求根（默认容差 0.01），调用前断言 `f(下界) <= 容差` 且 `f(上界) >= -容差`，否则抛错——所以边界算错会直接报错，不会静默画歪。

## 驱动循环

`task(onUpdate, signal)` 是一个 async 循环：

- `document.hidden` 时**不做动画**：模型已完成就直接跳到全长一次性交付；未完成则把 `x` 顶到当前全长、交付、然后 200ms 轮询。这是"没人看的东西不做逐帧演化"。
- 可见时每帧调一次 `_get_smoothed_completion()`，内容没变就不交付（`smoothed_completion_is_unchanged`）。
- 步长按面板可见性取 16.67ms 或 100ms，可见性回调结果缓存 1000ms 才重查。
- 终止条件是 `smootherDone`：强制完成，或模型已完成且已追平且期间没有块被改写。

另外两个入口：`restart()` 复位全部状态；`retract(index)` 截断块并**把 `x` 夹回新的总长**，然后按 `dont_smooth` 分流交付。

## 切片的粒度：思考与工具参数也在内

`fg()` 给出的 `blockSize`：

- `text` → `text.length`
- `connector_text` → 自身长度
- `thinking` → `1 + thinking.length + summaries.length`
- `tool_use` → `name.length + partial_json.length`
- 其它 → 0

`sliceBlock` 相应地把 `thinking` 留 1 个字符的余量（`slice(0, t-1)`），`tool_use` 从 `name` 之后开始切 `partial_json`。也就是说**思考文本和工具调用的流式 JSON 都走同一套平滑**，不是只平滑正文。

## 开关状态（本版本）

`dont_smooth` 这个串只出现在 3 个文件：

| 文件 | 出现 | 值 |
| --- | --- | --- |
| `shared-6-VPQPvNBR.js` | 类字段默认 | `!1`（false，即默认开启） |
| `shared-6-VPQPvNBR.js` | 调用点 `[157280,157620)` | `!0`（关闭） |
| `c06cf64bb-BLUe6JQe.js` | Code 会话缓冲 `Cm()` | `!0`（关闭） |
| `c37ff966e-D7aXsT1e.js` | challenger 内容 | `!0`（关闭） |

**本次查到的每一处显式构造都把它关掉了。** 上一份取证里 Code 的诊断导出也自报 `passThrough:!0, intervalMs:33`，与此一致。`reveal` 那组诊断计数器（`maxTextJump`、`maxBacklog`、`maxLeadInMs`、`shownText`……）正是这条**直通**路径的仪表：即使不平滑，他们也持续量"文字一次跳了多少""显示落后了多少"。

Chat 那份 bundle 里没有 `dont_smooth` 这个串，也没有显式赋值——**如果**它用默认值构造，那条路径就是开着平滑的。本报告没有追到 Chat 的构造调用，因此这条只是"与证据一致"，不是已证实。

## MP 可以采用的行为（独立实现，不抄代码）

| 现象 | 可迁移的行为 | 应证明的结果 |
| --- | --- | --- |
| 模型出字速度不均，界面跟着一顿一顿 | 把"到达"和"显示"分成两个量；显示量按帧独立演化，用到达历史算上下界 | 慢速到达时仍有推进，突发到达时不整段弹出 |
| 显示位置可能超前于实际内容 | 上界取已到达字符数，位置单调不回退 | 任何时刻显示的文字都确实已收到 |
| 落后越积越多 | 用"迟到线"（到达时间早于 `0.9t-0.3`）算下界，逼迫追赶 | 长回答末尾不会长时间停在半截 |
| 速度突变 | 速度走一阶惯性（α 取大），落后追赶期不更新基准 | 到达抖动不直接变成显示抖动 |
| 后台/隐藏标签页白跑动画 | `document.hidden` 直接跳到全长并降低轮询频率 | 隐藏时不消耗帧预算，切回来即完整 |
| 改写了已显示的块 | 截断后把显示位置夹回新总长 | 重试/压缩后不会显示已作废的内容 |

`γ`、`α`、滞后线这些**参数值本身不建议照搬**：它们与 Claude 的到达速率和渲染成本耦合。MP 应自己测一遍到达分布再定，验收看的是上面"应证明的结果"那列，不是数值相等。

## 边界

- 本机没有原始 TS、没有 sourcemap，全是编译产物；混淆名（`dg`/`fg`/`ag`/`sg`/`og`）是打包生成的，不是官方标识符。
- **没有运行 Claude UI**：没有实测帧时间、CPU/RSS，也没有确认用户账号下这些路径是否被远程开关覆盖。静态代码里"每处都关掉"不等于线上一定关着。
- **没有端到端验证**：没有验证 `arrivals` 在高频 delta 下的实际长度增长、`stats` 是否被上报、`0.9t-0.3` 这条线在真实速率下的表现。
- Chat 是否开启平滑未证实，见上。
- 许可证：闭源应用编译产物，未发现授权为开源库的依据。按 MP Reuse Gate，**只取行为、参数口径与验收样本，由 MP 独立实现**；精确切片只留在本地参考目录，不进 MP 生产代码。

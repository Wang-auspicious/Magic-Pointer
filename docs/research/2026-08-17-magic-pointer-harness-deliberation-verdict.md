> **输入：**仅《2026-08-17 Magic Pointer 下一代真实工作流 Agent Harness 独立研究底稿》一份文件，外加审议者对本机既往实测的少量本地事实（均单独标注）。未读仓库、未联网。
> **体例：**每处关键判断标注【事实】【推断】【假设】【决策】。凡是底稿中标为"官方自报"的数字（EvoX 70.87%、EvoHyper 23.5% 等），本审议一律按 B 级证据处理，不作为决策依据，只作为假设来源。
> ⛔ **本节结论已作废（2026-08-19）：**用户明确 Magic Pointer 就是要做顶级 Agent Harness 本身，短任务和长任务都自己做，任务时长不是边界；下方"自有 Runtime 只吃短任务、长任务交给 Hermes/Claude Code/Codex"是错的。现行边界见 `docs/design/MAGIC_POINTER_HARNESS_20260811.md` §1.1。本文保留为收缩路线的反方论证与风险清单，**不得作为边界依据**。

> **结论先行：**Magic Pointer 不应继续做"又一个更好的 Agent"。它应当收缩为一件事：**所有 Agent 的确定性感知前端与验证后端**——把"指一下+半句话"编译成最小充分输入，把"模型说完成了"替换成类型化回执；自有 Runtime 只吃短任务，长任务交给用户已有的 Hermes/Claude Code/Codex。原创壁垒押在三个机制上：**回执准入**（没有验证证据的经验永远不能晋升）、**指代置信度路由**（手势精度直接购买计算档位）、**可撤销的未来**（主动性=准备可回滚分支，用户结算，编辑差异即学习信号）。其余一切——超图、Swarm、多渠道、插件市场——90 天内明确不做。

## A. 残酷总判

（≤500 字）

**最强资产**：不是任何一个已实现模块，而是三条别人没有的确定性边界——FrameLease 冻结"用户当时看到的"、ActionLease 强制"写之前重新看一次"、屏幕内容永远是 data 不是 instruction。这三条合起来构成一个可辩护的立场：**模型负责判断，系统负责事实**。Hermes、Pi、Codex 都没有把"人类指代"纳入感知层的产品，这个位置目前是空的。【事实+推断】

**最大幻觉**：认为"已吸收六家源码的原语"意味着接近了它们的体验。原语不是系统。用户迁移发生在完整工作系统层，而 MP 当前的 Inbox 不跨进程、ask_user 不到 UI、Draft 不能改、账本不存在——纵向闭环在四处断开。第二个幻觉是"功能 parity 能跨越 Hermes 壁垒"：Hermes 一个补丁窗口合并 397 个 PR，追功能是必败的赛道。【推断】

**最大工程债**：账本闭环缺失。项目所有核心主张——更省 token、更少纠错、更快首步——目前**一条都无法测量**。没有账本，路由无法学习、记忆准入无法校准、楔子无法证伪。这比 WGC 缺失更致命，因为它让整个项目退化为"凭感觉迭代"。其次是核心再膨胀：Agent Loop 正在重演 Hermes 大循环。【事实】

**最可能的死法**：死在感知层的真实可靠性上，而不是死在架构上。本机既往实测已表明：UIA 探针在普通窗口上会成批超时（175ms 冷启动 + 200ms 硬超时，四个普通窗口全部失败），且 UIA 返回容器名而非文字时，"非空"被误当"读到了"。如果"指一下"在真实应用里三次有一次落空，用户会在第一周卸载——上层一切创新都建立在这个咽喉之上。第二死法是重演 2026-08-15：继续生产无生产入口的"漂亮大脑"和无人执行的研究文档。【本地事实+推断】

## B. 唯一产品楔子

### 主楔子【决策】

> **Magic Pointer 是你现有 Agent 的眼睛和手：指一下屏幕上的东西，它把对象、现场和你的半句话编译成最小充分输入，交给你已有的 Agent（或自己完成短任务），并用读回证据告诉你"真的完成了"。**

一句话版本：**deictic front-end + verified hand，for every agent you already use。**

为什么用户会为它先装一个"伴随层"而不需要迁移：

1. **零沉没成本冲突**。它不要求放弃 Hermes 的 Memory、Skills、渠道、习惯——它站在 Hermes 前面（编译输入）和后面（验证输出），中间不动。迁移心理学（底稿 4.2 两个 Reddit 样本）表明用户首先检查的是"已有资产能否继承"；伴随层根本不触发这个检查。【推断】
2. **它解决的是 Hermes 自己承认解决不了的事**。Hermes 的负面样本（重复下载 250 次、只列不做、任务混淆）全部是"模型自报完成 + 感知不接地"类失败。MP 的 FrameLease/ActionLease/Receipt 正好是这类失败的解药。【事实→推断】
3. **任务启动摩擦是可感知的日常收益**。每天几十次"这个、这里、把它"，每次省 30 秒 Prompt 组织时间，比任何 benchmark 都更能形成习惯。

### 备选楔子

**验证回执层（Receipt Layer）**：如果手势感知在真实应用中被证明不可靠（见 L 红队），退守为"给所有 Agent 的动作加读回验证和类型化回执"的纯后端层。价值密度更低但工程确定性更高，且与主楔子共享全部 Lease/Receipt 基础设施——这是一次真正的可回退设计，不是两个项目。【决策】

### 必须放弃的诱人方向【决策】

- **全功能聊天助手/多渠道**（Telegram/Discord/Slack）：这是 Hermes 的主场，每投入一天都在为对手的壁垒背书。
- **通用多 Agent 平台与 Swarm 产品化**：MP 任务 2–5 步，Swarm 的固定成本对 90% 场景是纯亏损（详见 I）。
- **插件市场/Skills Hub 生态**：生态是结果不是手段；没有日活之前建市场是给空城修城墙。
- **自动屏幕记忆/Recall 类全天候观察**：违反自身硬边界，且是信任的自杀。
- **动态超图作为通用知识层**：见 H，降级为任务事实表。

## C. Hermes 迁移与 parity 策略

### 四类能力表【决策】

| 类别 | 能力 | 处理方式 |
|---|---|---|
| **继承**（只读导入，MP 内可用） | Markdown Memory、Skills 文本、MCP server 配置、Provider/模型/密钥、工作目录习惯 | deja-vu 式**索引不摄取**：MP 建立本地索引指向 Hermes 原文件，永不改写原件；导入的记忆带 `provenance: hermes` 只读标签 |
| **代理**（Hermes 仍是执行方，MP 增值） | 渠道消息、Cron/长期任务、后台会话、浏览器长流程、Persona/Soul | MP 把编译后的现场上下文注入 Hermes 会话（作为一条结构化消息），并对 Hermes 声称的桌面动作做读回验证，把 Receipt 回贴 |
| **原生**（MP 独占实现） | 手势感知、FrameLease/ActionLease、DraftArtifact 直接编辑、类型化 Receipt、Memory Constitution、L0–L4 短任务 Runtime | 这是楔子本体 |
| **明确不做** | Telegram 等渠道 parity、Skills Hub、多 Agent Kanban、Persona 生态、Web Dashboard | 永久或至少 12 个月不做，文档里写死，防止 scope 回流 |

### 无破坏导入协议【决策】

1. **Dry-run 预览**：扫描 Hermes 目录，输出"将继承 N 条记忆 / M 个技能 / K 个 MCP，冲突 J 处"的报告，一个字节都不写。
2. **冲突报告**：同名技能、同义记忆、密钥重复，逐条列出，默认策略是"两存并标注来源"，绝不静默覆盖。
3. **影子模式**：导入后前两周 MP 只读不写——召回 Hermes 记忆时在 UI 上显示来源徽章，让用户看见"继承在起作用"。
4. **回滚 = 删除 MP 的索引**：因为从未改写原件，回滚是 O(1) 且零风险。这一点要在导入界面第一行写明。

### 先获益后迁移的顺序【决策】

第 1 天：MP 作为 Hermes 的输入编译器（指一下 → 结构化上下文进 Hermes）。第 1 周：MP 对 Hermes 的桌面动作出 Receipt。第 1 月：用户发现短任务在 MP 本地 Runtime 更快更便宜，自然分流。**永远不出现"请把任务从 Hermes 搬过来"的引导**——分流由账本上的延迟/成本数字驱动，不由产品话术驱动。

对底稿 4.4 的清单裁决：**必需继承面**只有 Provider/Model、Memory、Skills、MCP 四项；Session 搜索用索引方式继承；其余全部走代理或不做。

## D. 三个架构选项与单一推荐

### 选项 1：Full Harness（当前路线的延伸）

MP 建成完整独立 Agent 平台，功能上追平 Hermes 后以感知为差异点。
**否决理由**：追赶速度不可能（对方每 4 天合并 397 PR 且有 23 万 star 社区）；核心再膨胀已经在重演对方的维护问题；且"感知差异点"会被淹没在 80% 与对手同质的功能里，用户感知不到。这条路线的终点是一个二流 Hermes。【决策：否】

### 选项 2：Pure Peripheral（纯外设）

MP 完全没有自有 Runtime，只做感知编译器 + 验证器，一切执行交外部 Agent。
**否决理由**：短任务（复制、改一行、提取字段）经外部 Agent 绕一圈的延迟和成本荒谬——这恰是底稿第 8 节要消灭的浪费；无自有执行就无账本闭环、无 Procedure 沉淀、无数据飞轮；且命脉完全押在外部 harness 的接口稳定性上（Codex handoff 至今未稳）。【决策：否】

### 选项 3：Compiler-Core, Pluggable Engine（推荐）【决策】

- **确定性内核归 MP，永不外包**：捕获、感知融合、交互编译、Lease、权限、Receipt、Memory Constitution、账本。
- **认知引擎可插拔**：L0–L2 零模型/本地分类；L3–L4 单回合模型；L5 优先路由到用户已有外部 Agent（Hermes/CC/Codex），MP 自有 Loop 只作为无外部 Agent 时的兜底，且刻意保持 Pi 级极简。
- **工作系统归用户**：记忆、Procedure、Receipt、Draft 全部是可导出资产，换引擎不丢系统（底稿原创问题 7 的直接采纳）。

**比较**：选项 3 复杂度最低（自有 Loop 可以停止增长甚至收缩）、延迟最优（短任务不出本机）、token 最省（编译+分流）、可靠性边界最清晰（确定性内核小而稳）、迁移性最强（伴随层）、创新空间最集中（三个原创机制全部落在内核上）。它同时是唯一与 B 楔子和 C 策略自洽的结构。

**对现有代码的直接后果**：Agent Loop 停止吸收新功能，冻结为"L5 兜底"；工程投资转向内核四断链（ask_user UI、跨进程 steer、Draft 编辑、账本）和感知可靠性。

## E. 最小充分交互输入契约

### 对 normalized-1000 草案的裁决

方向正确，但草案在"看起来结构化"上超支。逐项裁剪：【决策】

**保留（模型可见）**：
- `frameLeaseId`、`stateVersion`（引用，不含坐标语义）
- `pointer`：`gestureKind` + `anchor` + `bounds` + **形状类别与端点**（圈/划线/点/框四类枚举）
- `nodes`：**默认 ≤8 个**（不是 16），字段收敛为 `id, role, name, bbox, state, confidence`
- `focused` + `deictic` 前 3 名及分数
- `evidence` 各 provider 的八态状态——**这是必留项**：`busy/timeout` 必须显式告诉模型"不是屏幕上没有，是我没读到"（本机"非空≠读到了"的教训直接写进契约）

**删除（模型不可见，留在确定性侧）**：
- `trajectory` 原始轨迹点（信息熵极低，token 纯耗损；形状类别+端点已是充分统计量）
- `scaleFactor`、`surfaceBoundsDip`、`origin`（纯执行侧元数据，模型见到只会诱导它谈坐标）
- `depth`、`coverage`（折进 confidence 一个数）
- `pruning` 细节（保留一行 `droppedNodes` 计数即可）

**预算**：首轮默认 **~400 token**（不是 900）；900 为硬上限。理由：8 节点 + 指代表 + 证据状态在 400 内可容纳；预算越紧，"渐进读取"才越真实。

### 渐进读取的期望价值门【决策】

不用另一个模型算 EVOI。用一个可判定代理量：**指代边际** `margin = deictic[0].score − deictic[1].score`。
- `margin` 高且任务动词不需要正文（复制/删除/点击类）→ 零补读；
- `margin` 低或动词需要文本（改写/翻译/总结类，来自一个 ≤30 词的封闭动词类表）→ `read_around` 一次；
- 证据八态含 `busy/timeout` 且命中区在该 provider 覆盖内 → 强制补读或明确降级声明，禁止让模型在"没读到"上作答。

### 跨轮指代衰减【决策】

废除"180 秒 TTL"这种物理时间机械律。锚点失效由三个事件驱动：目标 surface 的 `stateVersion` 变更且旧对象身份（UIA RuntimeId/DOM 节点）不再可解析；窗口关闭；任务边界（见 G 的事件分段）。对象仍可解析时，锚点跨十分钟也有效；对象没了，三秒也失效。时间只作兜底上限（如 30 分钟）。

### 用户纠正的微交互【决策】

不弹对话框。手势落点上渲染一个**高亮环**标出系统认定的"这个"，同时列出第 2、3 候选的淡环；用户不满意时**再点一下**即改判——一次点击完成纠正，且这次纠正进入个人指代模型（见 J 候选 2）。这是比 `ask_user` 便宜一个数量级的澄清通道；`ask_user` 只留给语义歧义，不用于空间歧义。

### 绝不进入执行坐标的字段

契约中**所有** bbox、anchor、归一化坐标。执行侧只接受"对象身份引用 + 当前 ActionLease 重新解析"。这一条写进 Schema 注释和代码断言两处。

### 成功指标

主指标取三个：**Grounding success**（首轮命中真实指代）、**Time-to-useful-first-step**、**每有效结果输入 token**。对照组：同一任务用纯文字 Prompt。指标定义直接复用第 16 节，不另造。

## F. Least-Sufficient Execution

### 分层裁决【决策】

七层太多，v1 收敛为**五层**：L0 确定性直达、L1 已验证 Procedure 回放、L2 本地路由、L4 单回合模型（小模型与 frontier 合并为一层，档位由路由选）、L5 完整 Agent（优先外部）。L6 Swarm 从执行分层中**整体移除**（见 I）。

### 各层可判定准入【决策】

| 层 | 准入条件（全部可判定，无 NL 猜测） | 失败处理 |
|---|---|---|
| L0 | 请求精确匹配一个 Capability 的显式签名（按钮/快捷指令/已知字段读取），参数全部来自 instruction 通道且通过类型校验 | 任何不匹配→L2；**永不重试** |
| L1 | 存在已验证 Procedure 且：环境指纹匹配（应用+版本+surface schema）、前置对象当前可解析、动作范围 ⊆ 原 Procedure 声明范围、上次 Receipt 为验证通过 | 回放中任一步骤读回失败→立即作废该 Procedure 本环境指纹项并升级 L4/L5；**不在本层重试** |
| L2 | 永远可进入（它就是路由器）。特征只用：gestureKind、surface 类别、封闭动词类、Capability schema 匹配度、指代边际——**零正文内容** | 分类置信度低→默认升级 L4，不询问 |
| L4 | L2 判定"需理解、无状态变更或仅可逆变更、预计单回合" | 模型请求工具或声明需要多步→升 L5，本层不给工具循环 |
| L5 | 其余一切 | 按现有 Loop（含 verification gate） |

**升级/询问的风险规则**：路由不确定时**默认向上升级，不问人**——除非候选动作含不可逆效果（发送/删除/支付/发布类 effect 标签），此时**必须问人**。阈值不是全局常数，是 effect 等级的函数。

### 防规则泥潭的三条硬律【决策】

1. **禁止手写关键词规则**。L0/L1 条目只能由两个来源产生：Capability 契约声明（开发者写的是类型签名不是关键词）、验证通过的 Procedure 自动沉淀（见下）。
2. **每次 L0/L1/L2 判定写入账本**，含"若升级会怎样"的逃逸记录；误路由率按层统计，超阈值（建议 5%）该层自动收窄准入。
3. **Procedure 不是聊天转技能**。一次成功不沉淀；沉淀条件=Receipt 验证通过 **且** 第二次在同环境指纹下回放成功（首次回放在影子/确认模式下进行）。沉淀物是结构化合同（前置、对象类型、动作序列引用、验证方法、有效环境指纹、失效计数），绑定到**对象身份类型**而非像素或窗口句柄。

### Intelligence Density 账本【决策】

每个"被验证有用的结果"记一行：路径层级、模型档位、输入/输出 token、美元、工具调用数、墙钟、人工介入次数、验证方式。两个导出指标：**每有效结果成本**（分层对比）与**分流率**（L0–L2 消化的请求占比，目标 ≥40%——若达不到，说明楔子场景本身不成立，这是一个诚实的证伪器）。账本是 90 天计划的第一优先工程项（见 K）。

## G. Memory Constitution

### 最小类型集【决策】

v1 只要五型，砍掉四型：

| 类型 | 采用？ | 写入准入 | 批准者 |
|---|---|---|---|
| Raw Episode | ✅ | 一切任务无条件 append-only（事件、证据引用、动作、Receipt、成本、用户修改） | 系统自动 |
| Working Set | ✅ | 会话内暂存，任务边界即弃，永不落长期 | 系统自动 |
| Preference | ✅ | ≥3 次独立同向选择，**或**用户显式"记住这个"，**或**Draft 编辑差异的稳定模式（见 J 候选 3） | 自动候选+用户可见确认 |
| Procedure | ✅ | 唯一入口=F 节的双重验证（Receipt 通过 + 二次回放成功）。**没有外部证据的成功永远不能晋升**——这是宪法第一条 | 系统自动，用户可废止 |
| Anti-pattern | ✅ | 一次验证失败且有成本记录即可写（失败比成功便宜采信，因为误报代价不对称） | 系统自动 |
| Semantic Fact | ⏸️ 降级 | 只收用户显式保存项与 Hermes 导入项；**不做自动抽取**（Hindsight 式反思写入错误模型的风险 > 收益） | 用户 |
| Mental Model | ❌ v1 不做 | —— | —— |
| Routine/Prospective | ⏸️ 延后 | 前瞻条件（"X 状态出现时提醒 Y"）是好机制，但依赖事件分段成熟，放 90 天后 | —— |
| Handoff Artifact | 重分类 | 它是 **transport 不是记忆**——归入 Receipt/Artifact 体系（见 I） | —— |

### 生命周期裁决

底稿 9.3 的九步框架基本采纳，四处修订：【决策】

- **Consolidate 由惊奇门控**（神经科学"预测误差"的操作化）：只有三种信号触发巩固——验证失败、用户纠正（含改判指代、编辑 Draft）、路由误判。顺利完成的任务只留 Episode，**不产生任何长期记忆**。这从根源消灭"每任务都写记忆"的噪声。
- **Retrieve 用导航面**：每轮注入一个 ≤300 token 的索引（名字+一行钩子，与 Claude Code MEMORY.md 同构），Agent 按需展开 L1/L2；展开路径记入账本，高频路径提升该条目在导航面的排序（检索经验本身可学习，底稿原创问题 9 的采纳）。总注入硬上限维持 4000 字符不涨。
- **Resolve**：冲突两存 + 有效期区间，检索时消解（APEX-MEM 思想采纳其原则、不采纳其重结构化抽取）。宪法条款：**任何自动流程不得删除或改写既有记忆正文**，只能追加、降权、标失效。
- **Decay**：Procedure 按环境指纹失配计数退役；Preference 遇 2 次反向选择降为候选。无使用不是退役理由（低频≠错误）。

### 神经科学：采用与否逐条表态

- **采用并已操作化**：门控=准入规则；互补学习系统=Episode（快、具体）与 Preference/Procedure（慢、验证后）分离；再巩固=Procedure 仅在"回放失败→修复→再验证"循环后允许更新且保留旧版本；事件分段=任务边界由 Lease 生命周期+窗口身份+目标达成共同判定；惊奇=巩固门控信号。
- **不采用**：睡眠重放/Dreamer 式离线整理（Magic Context 路线）——离线过程"梦出新事实"的风险无法用本项目的验证手段约束；提取诱发遗忘的对抗机制——过度设计，用 Anti-pattern + 排序衰减已覆盖其目的。

### 不采用的流行方案及理由【决策】

向量库作为主检索（词法+结构先行，deja-vu 证据表明继承场景够用；embedding 只在词法失败时作为第二路）；OpenViking 三层全文摘要（写入成本对 2–5 步短任务倒挂，且 AGPL）；Magic Context 替换宿主 compaction（侵入性+双真源冲突）；EvolutionEvent 全审计协议（借鉴 Capsule 的字段思想进 Receipt，不引入其协议复杂度，GPLv3 与混淆代码也排除直接复用）。

### 迁移与证明

Hermes 记忆按 C 节索引式继承，召回时带来源徽章，永不改写。**优于短 Markdown 的证明方式**：同一批真实任务，对照组=现状 4000 字符注入，实验组=导航面+按需展开，比较 Memory precision、每有效结果输入 token、澄清次数。若无显著差异，**保留短 Markdown 并停止记忆工程**——这是本宪法自带的证伪条款。

## H. 主动性与动态超图

### 主动性：权力边界【决策】

采纳底稿 10.2 的七级权力梯度，外加一条统摄原则把它从"清单"变成"机制"：

> **主动性 = 准备可撤销的未来，而不是预测并执行一个动作。**

- 1–2 级（预取、灰显补全）：零许可，因为撤销成本为零；但预取范围限定于当前 FrameLease 关联对象与导航面，**禁止**为预取扩大观察面（回应 10.3 问题 2——合法上下文=当前手势+当前窗口+近期 Episode+已晋升 Preference，不含持续监控）。
- 3–4 级（单一建议、备好草稿）：每回合最多**一个**建议，必须附依据链（哪条 Preference+哪个当前对象）；草稿只生成不发送。
- 5 级（可逆动作）：仅在既有授权范围+当前 ActionLease 内。
- 6–7 级：不变，不可逆动作永不因习惯自动升级。

**等级移动规则**：只升不跳——某类建议的历史接受率 ≥60%（≥10 样本）才允许从 3 级升 4 级；出现一次"接受后又撤销"立即降一级。个体阈值就是这张分类接受率表，无需模型学习。**优化目标**采纳 10.3 问题 3 的表述：净节省人类操作量 −（误报次数 × 打断成本），按周在账本出数。

**意图补全的对象**（10.3 问题 1 的回答）：是**用户最终希望看到的状态**（一个可展示的 Draft/预览），不是下一句话也不是下一工具——因为状态可被一眼验收、可被编辑、可被撤销，而"替用户说话"和"替用户选工具"都不可验收。

**最小反事实确认**：当前两个意图候选分数接近时，问一个二选一（"翻译成英文，还是润色中文？"），选项即候选本身，点击即执行编译。禁止开放式"您想要什么"。

### 动态超图：不采用【决策】

对 11.2 八问的直接回答：MP 没有一个痛点**必须**超边才能解决。EvoHyper 针对的"同一事实复制 2.8–4.1 次"在 MP 语境下的真实病灶是转述，解药是更简单的结构：

> **任务事实表（Task Fact Table）**：每个任务一张扁平表，每条事实一行——`id, 类型, 值/引用, owner（产出者）, 证据引用, 状态（claimed/verified）`。Prompt、消息、记忆**引用行 id，不复制内容**；验证后状态翻转；任务结束时 verified 行直接构成 Receipt。

它消灭三份复制（超图候选语义的全部实际收益），实现成本约为超图的 1/10，模型无法改写它（只有确定性代码在验证后翻状态），且天然与 I 节的 Swarm transport 同构。**物化阈值**：单 Agent 2–5 步任务连表都不建，Working Set 够用；只有多执行单元或步骤 >5 时物化。若未来出现"一条事实同时约束多个并行单元且需要整体失效"的实测需求，再评估超边——目前这是一个不存在的需求。【决策：超图不进入路线图】

## I. Swarm 与经验网络

### 默认单 Agent，展开门槛【决策】

全部满足才允许展开（任一不满足即禁止）：

1. 任务可枚举为 **≥8 个**原子项，各项有稳定 ID 与独立输入；
2. 每项结果有 Schema 且可**程序化合并**（按 ID 落位，零 LLM 汇总）;
3. 每项有独立验证方法；
4. 各项不写同一资源——**每个 Surface 同一时刻至多一个执行单元持有 ActionLease**（硬律）；
5. 无任何不可逆动作参与；
6. 账本预估：并行收益 > 启动成本（有历史同类数据支撑，无数据则默认不展开）。

**绝对不用 Swarm 的场景**：交互式桌面操作、含发送/删除/支付的任务、步骤间强顺序依赖、用户在旁等待的实时任务。

### 原子任务与 transport【决策】

原子任务 Schema：`{id, input_refs（事实表行/Episode 引用，非全历史）, output_schema, 完成合同（验证方法）, budget, owner}`。worker 起步上下文=任务合同+相关事实表行+记忆导航面，**不复制主 Agent 历史**（回应 12.2 问题 1）。

**反摘要 transport（EvoX 教训的直接采纳）**：worker 结果写入事实表预定行位，类型化字段直达 Receipt/Draft；**任何 verified 行禁止再经 LLM 转述**；只有无法结构化的残余（如"备注"）允许 ≤100 token 摘要。程序负责检查覆盖/重复/缺口/失败并触发定向重试。Correct-result retention 目标 ≥95%（对照 EvoX 报告的 55.5% 病灶——该数字虽 B 级，病灶机制是可信的）。

### 经验晋升（12.2 其余问题）【决策】

worker 局部发现 → 事实表 claimed 行 → 验证 → verified → 任务结束随 Receipt 归档进 Episode；**长期晋升走且仅走 G 节宪法**（Receipt 准入），worker 没有独立的长期记忆写入权。冲突事实两行并存，由验证消解，无仲裁 LLM。worker 专长=账本上按能力×环境统计的成功率，是路由权重不是身份标签，随窗口衰减（回应"不被旧身份锁死"）。

**对照实验**：同一批可枚举任务（如"提取 20 个文件各自的某字段"），单 Agent 顺序 vs 展开，比较 token、墙钟、verified 完成率、retention。若展开不能同时赢两项，抬高门槛。

## J. 12 → 3 原创机制淘汰赛

### 12 个候选（一句话机制 + 淘汰判语）

1. **手势即预算路由**：指代边际直接决定感知深度、模型档位、首轮工具预算。→ **晋级**（并入决赛 2）。
2. **个人指代模型**：每次改判更新一个可解释的特征权重表（角色偏好/邻近权重/近因权重），不存像素。→ 强，但依赖决赛 2 先证明边际信号有效，降为其二期。
3. **Draft 编辑差异学习**：用户改了哪、怎么改，作为高密度偏好信号。→ **晋级**（并入决赛 3）。
4. **工具调用=信息购买**（显式 EVOI 计算）：诚实计算需要再调一个模型，违背初衷；其可判定近似已被候选 1 吸收。→ 淘汰。
5. **状态缺口驱动工具选择**：按"预期下一状态 vs 当前状态"选工具。→ prior-art 撞车 HyperAgent 的 deficit-oriented expansion，且需维护全量工具 Schema 图。→ 淘汰（思想留给 Capability 契约设计）。
6. **验证即记忆准入**：无外部证据的成功永不晋升。→ **晋级**（决赛 1 核心）。
7. **可替换认知引擎**：已在 D 作为架构采纳——它是结构决策，不是机制创新。→ 移出淘汰赛。
8. **反摘要 transport**：已在 I 采纳；单独看与 EvoX 原则同源，原创性不足以单列。→ 并入决赛 1（Receipt 即 transport 单元）。
9. **导航面记忆+可学习展开路径**：已在 G 采纳；L0 索引与 OpenViking 撞车，可学习展开是增量而非跃迁。→ 淘汰出前三。
10. **惊奇门控巩固**：已在 G 采纳；与 GAM/事件分段文献同向，是好工程不是壁垒。→ 淘汰出前三。
11. **可撤销的未来**：主动性=准备可回滚分支，用户结算。→ **晋级**（决赛 3 核心）。
12. **任务事实所有权表**：已在 H 采纳；是超图的减法替代，价值在"不做什么"。→ 并入决赛 1 的支撑结构。
13. **跨用户合同资产**（共享验证合同/失败模式，不共享内容）：需要用户规模，90 天内不可证伪。→ 淘汰（存档为二年期方向）。
14. **迁移数据自动发现 20% 依赖面**：好功能，机制含量低。→ 淘汰，作为 C 节的实现细节。

### 决赛三名

#### 🥇 决赛 1：回执准入（Receipt-Gated Experience）

- **一句话机制**：类型化回执（Receipt）是同一个数据结构的四重身份——交付证明、Agent 间 transport 单元、Procedure/记忆的唯一准入票、账本的记账行。**没有 Receipt 的一切"成功"在系统中不存在。**
- **解决的失败链**：模型自报完成→假成功被记住→坏 Procedure 被回放→错误固化（Hermes 负样本的完整病理）；以及正确结果在转述中丢失（EvoX 55.5% 病灶）。
- **prior-art 差异**：Hermes verification stop 只拦截结束、不控学习；EvoX Capsule 记录结果但不作准入门；Shepherd retained output 限于代码工作区。**把验证与学习准入焊死成一个结构**，未见先例。
- **接入 seam**：现有 verification gate + Session JSONL + Draft 体系，全部已存在。
- **最小数据结构**：`Receipt{task_id, effect 声明, 验证方法, 读回证据引用, 状态, 成本行}`。
- **一周实验**：20 个真实短任务，开/关准入门，两周后比较 Procedure 回放成功率与 Memory pollution。
- **放弃条件**：若可验证任务占比 <30%（多数桌面动作读不回来），机制覆盖面不足，降级为可选特性。
- **壁垒**：用户积累的是"被证明过的经验库"，跨引擎可携带——换模型不丢，这是不锁定的飞轮。
- **最大副作用**：验证工程是 O(应用) 的苦活；读回失败会被误判为动作失败（需八态区分"没读到"与"没做成"）。

#### 🥈 决赛 2：指代置信度路由（Deictic-Confidence Routing)

- **一句话机制**：编译产物携带指代边际与证据完备度两个标量，确定性地同时决定：是否补读、感知深度、模型档位、首轮工具预算——**手势精度直接购买计算便宜度**。
- **解决的失败链**：简单任务照走完整 Agent 回合（成本/延迟）与模糊输入硬塞给便宜路径（错误）这对孪生浪费。
- **prior-art 差异**：OpenSquilla 按文本特征路由、ProcAgent 按歧义触发视觉——都没有人类手势几何作路由信号，因为**只有 MP 的输入里有手势**。这是位置独占的机制。
- **接入 seam**：交互编译器输出 → `run_agent_turn` 入口 + F 节 L2 路由器。
- **最小实验**：先纯观测两周——记录每次任务的边际值与最终结局（是否澄清/误指/升级），验证边际对失败的预测力（AUC>0.75 才上线路由）。
- **放弃条件**：边际不预测失败，或用户手势精度个体差异大到无法用同一映射。
- **壁垒**：越用越准（个人指代模型二期），且竞品无此输入通道可抄。
- **最大副作用**：用户可能学会"故意画大圈骗预算"——需上限约束；感知层不可靠时边际本身是噪声（依赖 A 节咽喉问题先解决）。

#### 🥉 决赛 3：可撤销的未来（Revocable Futures）

- **一句话机制**：主动性只允许产出可撤销分支（预取证据、灰显补全、预备草稿）；用户的选择结算分支，**用户对预备草稿的编辑差异**作为最高密度学习信号进入 Preference 准入。
- **解决的失败链**：Persona 式"要主动"产生高成本错误主动（Hermes 负样本、PersonalAlign ~70% false alarm）；以及点赞/踩信号密度太低学不到东西。
- **prior-art 差异**：PersonalAlign 建议动作但不绑定可撤销性；Shepherd 的候选世界限于代码。**"权力等级=可撤销性等级"+"编辑差异=准入信号"的闭环**未见先例。
- **接入 seam**：DraftArtifact 版本化（已有数据结构）+ G 节 Preference 准入。前置依赖：Draft 直接编辑断链必须先修（本来就在 K 的第一阶段）。
- **最小实验**：手势落定、用户话音未落时预生成草稿，测接受率、净节省输入量、打断感（主观 5 分量表）。
- **放弃条件**：接受率 <30% 或用户报告打断感 >中位 3 分。
- **壁垒**：编辑差异数据是纯私有、逐用户累积、不可被通用模型替代的对齐资产。
- **最大副作用**：预生成消耗 token（需限于 L4 以下档位）；灰显补全若质量差会训练用户忽略整个通道。

三者非拼装的自证：回执准入改变**学习准入结构**，指代路由改变**计算分配结构**，可撤销未来改变**权力与信号结构**——各自是对信息流/权力边界/学习准入的重排，且两两独立可单独证伪。

## K. 90 天研究—产品路线

每阶段一个假设、一组对照、明确停止条件。**阶段 0 贯穿全程的删除令**：冻结 Agent Loop 功能吸收；删除一切无生产入口的模块（复查 2026-08-15 式残留）；插件市场、渠道、Swarm、超图代码路径明确封存。

### 第 1–4 周：假设 A——"编译输入优于打字 Prompt"

- **做**：E 节裁剪版输入契约接入生产；修四断链中的两条（Draft 直接编辑、高亮环纠正）；**建账本**（本阶段第一优先，没有它后面全是感觉）；感知咽喉攻坚：UIA 超时预算与像素兜底策略修复（本机实测的 200ms 全灭问题），八态贯通到编译产物。
- **用户任务**：10 类日常短任务（提取、改写、复制、填入、翻译等），每类真实应用。
- **对照**：同任务纯文字 Prompt（可用 Hermes/CC 作对照执行方）。
- **指标**：Grounding success ≥85%、Time-to-useful-first-step 减半、每有效结果输入 token 减 ≥40%。
- **停止条件**：Grounding <70% 且两周修不上去 → 楔子换备选（Receipt Layer），感知层降为辅助。

### 第 5–8 周：假设 B——"回执准入让重复任务变便宜"

- **做**：Receipt 数据结构 + 5 个真实应用的读回验证（Office 两个、浏览器、资源管理器、终端）；L1 Procedure 回放 + 双重验证准入；F 节 L0/L2 分流上线；决赛 2 进入纯观测（记录边际，不路由）。
- **对照**：同一重复任务第 N 次执行，回放 vs 全新回合。
- **指标**：Procedure reuse yield >0、Verified completion ≥90%、分流率 ≥40%、Memory pollution <10%。
- **停止条件**：可验证任务覆盖 <30% 或回放成功率 <80% → 回执准入降级，资源转向假设 C。

### 第 9–12 周：假设 C——"Hermes 用户愿意装伴随层"

- **做**：C 节导入协议（dry-run/冲突/影子/回滚）；MP→Hermes 上下文注入 + Receipt 回贴；deja-vu 式历史索引；决赛 2 若观测达标则开启真实路由；决赛 3 最小实验（预备草稿）。
- **用户**：≥10 名真实 Hermes/CC 用户（含开发者自己的日常）。
- **指标**：Migration retained value ≥80%、伴随层第 4 周留存 ≥50%、Proactivity net value >0。
- **停止条件**：留存 <25% → 承认伴随层假设失败，收缩为个人工具/垂直场景，重估商业面。

**90 天内明确不做**：WGC 之外的新感知源、Swarm、超图、多渠道、Semantic Fact 自动抽取、跨用户共享、Skills 市场。WGC 作为并行基建推进但不阻塞任何阶段验收。

## L. 红队反驳

**Hermes 重度用户**："我的工作流长在键盘和终端里，'指一下'对我是降速；导入再无损我也怕它动我的目录；你回贴的 Receipt 在我的 Hermes 会话里是噪声。"——最痛的一击是第一句：**楔子隐含假设了鼠标/触控中心的用户画像**，而 Agent 早期采用者恰恰是键盘中心人群。若第 12 周留存失败，首先检查的应是画像错配而不是实现质量。

**Pi 极简主义者**："你们批判 Hermes 膨胀，然后造了输入契约、五层路由、记忆宪法、回执体系、事实表——这本身就是一台复杂度机器。400 token 的'最小'契约里有多少字段模型根本不看？"——正当质疑。解药已内置（每字段消融、账本证伪），但红队正确指出：**这些证伪条款执行起来需要纪律，而本项目 8-15 事件证明纪律恰是短板**。

**企业工作流负责人**："你们自己的实测显示 UIA 在普通窗口成批超时；我们的应用是 Delphi/Java Swing/远程桌面/自绘 Canvas，UIA 树是空的。SurfaceAdapter 契约意味着每接一个企业应用都是定制工程——这是 O(应用) 的 RPA 老路，UiPath 用一千人趟过。"——**这是全篇最重的反驳**：感知可靠性不是一个 bug 是一条成本曲线，且历史上压垮过整个行业的产品。MP 的回应只能是收窄承诺面（明确支持矩阵）+ 像素/OCR 兜底常开，而不是假装 UIA 够用。

**HCI 研究者**："高亮环+再点一下未经用户研究；灰显补全在 IDE 里成立是因为补全即文本，桌面上'补全意图'的可视化语法根本不存在；你们所有指标都测系统效率，没有一个测用户的信任与控制感。"——采纳：第 1 阶段必须含 ≥5 人的真实用户观察（哪怕非正式），Focus-steal 与主观信任量表进入主指标。

**系统工程师**："ActionLease 在虚拟列表/懒加载 DOM 上重解析会系统性失败——对象身份在这些 UI 里本来就不稳定；读回验证在异步应用里有竞态（写成功但读回时机太早）；Receipt 的'验证方法'字段最终会退化成每应用一坨脆弱脚本。"——技术上最具体的一击。对策是把"对象身份可解析性"本身纳入 Capability 契约声明（不可稳定解析的 surface 直接降级人工确认），但红队正确预言了长尾的丑陋。

### 什么证据会让我推翻自己的推荐

1. 第 4 周对照显示打字 Prompt 在多数任务上 Time-to-useful-first-step 更优 → 推翻主楔子。
2. 指代边际对失败无预测力（AUC≤0.6）→ 推翻决赛 2，指代路由降为固定预算。
3. 可验证任务覆盖率 <30% 且读回工程边际成本递增 → 推翻决赛 1 的中心地位，回执降级为可选审计。
4. 伴随层用户留存 <25% 且访谈显示"不愿在 Hermes 之外再开一个常驻进程" → 推翻伴随层战略，此时正确动作不是加功能，而是把交互编译作为库/协议**卖给** Hermes 生态（成为上游），彻底放弃独立产品形态。
5. 若 90 天内团队再次出现"写了机制没有生产入口"的审计发现 → 问题不在架构在执行方式，应先修流程（每个 PR 强制声明接入 seam 与可测指标）再谈任何创新。

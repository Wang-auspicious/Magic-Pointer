# GOAL — 2026-09-16 Mainline Quality Pass

## Acceptance bar (do not lower)

A run counts as passing only if ALL of the following hold, with evidence committed to this repo:

1. **≥100 distinct defects/improvements** enumerated in `docs/BUGLEDGER_20260916.md`, each with
   `file:line`, root cause, fix commit SHA, and status (`fixed` / `verified` / `rejected-with-reason`).
2. **Latency**: measured end-to-end first-response p50 on a warm run is materially lower than the
   recorded baseline (voice p50 4.3s per `docs/` audit). Numbers measured by the repo's own harness,
   pasted into the ledger. No hand-waving.
3. **GUI smoothness**: the on-screen pointer/overlay path holds its frame budget in a real run —
   no per-frame full re-layout, no main-thread blocking IPC on the hot path. Twin-cursor behavior
   reaches at least Clicky's observable capability set on Windows.
4. **Complex-task survival**: a multi-step desktop task runs to completion without the loop stalling,
   double-firing a tool, or losing the trajectory — parity-worthy against dsh / Hermes / Claude Code
   harness behavior on the same class of task.
5. **Circle-and-point (圈点) reliability**: annotation → prompt round-trip is deterministic across
   repeated strokes, window switches, and DPI changes.
6. **Verification**: a dedicated verifier agent re-runs each claimed fix from a clean checkout and
   records an independent pass/fail. Claims without a verifier sign-off are `unverified`, not `fixed`.

## Method

- Reference sources are read **line by line**; we are porting behavior, not protocols.
- Every fix lands on `main` and is pushed. Small commits, often.
- Subagents: max 5 concurrent workers + 1 dedicated verifier. Handoff prompts must name exact files,
  exact symbols, exact acceptance command, and exact evidence artifact.

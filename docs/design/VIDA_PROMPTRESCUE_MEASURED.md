# PromptRescue 逐像素测量档案（2026-09-02）

素材：`参考/Vida/PromptRescue.mp4` — h264, **1920×1080, 60fps, 35.000s, 2100 帧**。

## 0. 先说一个会毁掉复刻的事实

**这段视频带推拉镜头，不是 1:1 录屏。**

证据：macOS 菜单栏在 t=1.0s 占 26 行黑像素，在 t=14.5 / 15.5 / 17.0 / 21.0 / 23.0 / 27.0 / 28.5 全部为 **0 行**——画面已被推近，菜单栏被推出画外。

因此**任何跨时间点的绝对像素值都不可比**。本文所有几何一律记为：

- 该帧内的绝对像素（可复核）；
- **相对胶囊自身高度 h 的比值**（缩放不变量，这才是复刻依据）。

复刻时先定 `h`，其余全部由比值导出。这样在任何 DPI、任何胶囊宽度下比例都不会失调。

测量方法：Pillow 逐像素扫描，阈值取背景与面板亮度的中点；圆角用 `inset(dy) = r - sqrt(r² - (r-dy)²)` 拟合，两个独立采样点误差 ≤1px。

## 3.5 TASK FINISHED 审批卡（t = 22.0s）

镜头位置与 §1 不同，**不要拿这里的绝对像素去和胶囊比**。本节的换算单位是**按钮高 111px**。

### 外框

| 项 | 视频像素 | 说明 |
|---|---:|---|
| 卡片框 | x=121, y=360, **1668 × 605** | 高度随正文行数变化，**不是固定值，不要钉死宽高比** |
| 圆角 | 55 | 与胶囊共用同一枚 token（见下） |
| 表面色 | (249,248,251) | **#F9F8FB**，与胶囊同色 |
| 分隔细线 | y=767 | 卡顶下 407px；底栏高 **197** |

### 底栏与按钮

| 项 | 视频像素 | ÷ 按钮高(111) |
|---|---:|---:|
| Reject（描边） | **208 × 111** | 宽 1.874 |
| Approve（实心） | **250 × 111** | 宽 2.252 |
| 按钮圆角 | 29 | **0.261** |
| 两钮间距 | 42 | **0.378** |
| Approve 右缘 → 卡右缘 | 47 | **0.423** |
| 底栏总高 | 197 | **1.775** |
| Approve 填充 | (25,25,25) | **#191919**，与发送键同色 |
| Reject 填充 | (251,251,251) | 描边，非实心 |

按钮纵向在底栏内居中：上距 45，下距 47。

### 圆角是一枚定值 token，不是按比例缩放的

同一帧内：卡片圆角 **55** / 卡高 605 = 0.091；按钮圆角 **29** / 按钮高 111 = 0.261。若圆角随高度缩放，605 高的卡片圆角应在 190 上下，实测 55。**只能是定值。**

跨帧核对：胶囊圆角 64 @ t14.5（该帧胶囊高 202），同一胶囊在 t21 高 190 → t14.5→t22 的缩放约 1.07，把 64 归一到 t22 尺度得 ≈60，与卡片的 55 同量级。差值在带阴影边缘的拟合误差内。

**结论：面板类（胶囊、卡片）共用一枚圆角 token；按钮用另一枚，约为前者的 0.53。**

### 一处不能照抄的冲突

按 Vida 比例，胶囊高 : 按钮高 = 188 : 111 = 1.694。MP 胶囊定为 56px，等比推得按钮应为 **33px**。

但 `stage.css` 里那条注释是实机踩出来的：「42px 高不是为了好看——上一版 4px 内边距的文字按钮，在一块浮在别人窗口上的面板里根本点不准。」

**本批保留 42px，只把形状比例（圆角、间距、右内距、底栏高、填充色）套到 42px 上。** 缩到 33px 是可用性回退，不在没有真机复测的情况下做。

### 结构与 MP 现有的 `.stage-thread` 一一对应


证据行用 `✓` 起头、`→` 做行内分隔，段内自动换行。

### 行距（14 条墨带逐条量出来）

| 项 | 视频像素 |
|---|---:|
| 标题墨带高 | 29 |
| 正文段内行距 | **38, 39, 38, 39, 39, 39** → **38.7** |
| 段与段行距 | **79, 77, 72, 76** → **≈75** |
| 正文升降部墨迹高 | 22–29（有升有降时 29） |

**段间距 ≈ 2× 行距**（75 / 38.7 = 1.94），即段落之间空一行。

行距比 = 38.7 / 29 = **1.334**。按墨迹约占 0.93em 反解，字号 ≈31.2，**line-height ≈ 1.24**。

### 与审批卡交叉验证

审批卡正文（§3.5 同法）：行距 **47**，`C` 帽高 27 → 字号 ≈38.6，升降部墨迹 34.5。
行距比 47 / 34.5 = 1.362 → **line-height ≈ 1.27**。

**两张卡独立测得 1.24 与 1.27，互相印证。** MP 原来是 **1.58**，明显偏松，已改 **1.25**。

### 证据行是折行的，不是一行省略号

参考里每条证据都是**折到三行的完整段落**（`✓ Reviewed latest Slack messages → User feedback on design is positive → Need to address concerns about the color scheme`）。

MP 的 `cards.css .mstep-label` 是 `white-space: nowrap` + `text-overflow: ellipsis`。**被省略号吃掉的恰好是 `→ 所以要做什么` 那半句**——一条证据里唯一有行动价值的部分。

已在**舞台域**改为折行（`.stage-result .mstep-label`），并把段距从 10px 提到 18px（参考段距/行距 = 1.94，即空一行）。同步把 `.mcard-steps li::after` 的脊线 `bottom` 从 -10 改到 -18，否则脊线断成一截截。

**为什么只改舞台域**：`cards.css` 是 `studio_system.css` 的 8 个合并源之一，改共享文件会牵动 237KB 的重生成，且会同时改动 Studio 与 Companion。舞台域覆盖拿到同样的 1:1 结果，血溅面小得多。

### 脊线已删，绿勾保留

参考的证据行只有 `✓` 前缀，**没有竖脊线**。脊线原是「状态住在活动脊上」那一版的产物；状态已经搬回卡头的眉毛行（见 §3.7），脊线没有承载物了，`display: none`。

绿勾（`.mstep-dot`）保留——它就是参考里那个 `✓`。

## 3.8 胶囊入场（11.6–12.9s 逐帧，60fps）

| 阶段 | 实测 |
|---|---|
| 淡入 | 表面亮度从背景线性升到满值，**12.514 → 12.700 ≈ 186ms** |
| 上浮 | 淡入结束后 top 764 → 757，**7px / 183ms** |

期间宽高全程恒定 **1773 × 202**，且左侧背景标记行恒在 y=596 不动——**排除镜头运动，是纯不透明度淡入，不是缩放**。

7px / 202 = **0.035h**，56px 胶囊上折合 **2px**。已落地为 `stage-composer-appear 186ms linear` + `stage-composer-settle 183ms`（延迟 186ms 起）。

## 3.9 逐行入场：测不准，不编

30fps 全程扫过 16.5–23.5s，卡内墨带数是 **5→6→5→4→3→2→3→6→8→9→12→14→15**——忽增忽减。原因是**文字流式写入和卡片自动滚动同时发生**，行既在生成也在滚出视野，墨带数不是「第几行出现了」的干净信号。

**这支片子给不出可信的单行入场间隔。** 保留既有的 `mstep-in 360ms`（那是从另一支 Vida 片子逐帧测的，`cards.css` 注释里记着 350–400ms）。要拿到这支的数，得做逐行文本内容比对，不是数墨带。

## 5. 复核方式

```bash
ffprobe -v error -select_streams v:0 -show_entries stream=width,height,r_frame_rate,nb_frames,duration \
  -of default=noprint_wrappers=1 "参考/Vida/PromptRescue.mp4"
ffmpeg -v error -ss 14.5 -i "参考/Vida/PromptRescue.mp4" -frames:v 1 t14.5.png -y
```

胶囊外框：取 x∈{1400,1450,1500,1550} 四列的近白（luma ≥ 240）纵向交集得 y=756..957；再在 y=top+20 这条无文字无按钮的扫描线上左右外扩得 x=85..1823。

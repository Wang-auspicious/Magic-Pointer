一 · 玻璃，做对的版本

B 的问题不是"玻璃"，是玻璃只有一层：背景直接透到文字底下。真机做法是两层——模糊层负责质感，文字底下另铺一块高不透明度的板负责可读，深背景上再自动加厚。Apple 后来给 Liquid Glass 加的不透明度滑块补的就是这一层。

四 · 和现在的代码差在哪（实测计数）

现在标准为什么
stage.css 里 :active 按压反馈 0 处transform:scale(.97)按下去没反应＝界面没在听。这是"廉价感"最大的单一来源
ease-out 内置曲线 21 处cubic-bezier(.23,1,.32,1)内置曲线太软，缺少"这是故意做的"那种力度
手搓曲线 8 种，含 cubic-bezier(.4,0,.2,1) ×5只用标准表里的 3 条规则里点名：不要因为眼熟就发明这条
@media (hover:hover) 0 处所有 hover 动效都要门控触屏点一下会触发假 hover
stage.css 有 7 处动 width/height/top/left只动 transform/opacity布局属性会触发 layout+paint，掉帧
stage.css 25 个 @keyframes可快速重复触发的用 transitionkeyframes 被打断会从头开始，transition 会从当前值接上
dashboard.css 只有 2 个 keyframes、1 处减弱动效错峰进场 + 高亮块位移配置页现在几乎没有动效，这就是"基本不变"的原因
stage.css font-weight:500 仅 1 处正文基线 500半透明浮层上 400 字重发虚

另外两个真 bug：--stage-ink-soft 和 --stage-ink-faint 是自引用（--x:var(--x)），CSS 里等于无效值，5 处文字颜色实际继承了父级；.stage-capsule 有两个冲突的规则块，前一个石墨黑被后一个浅色整个覆盖，是死代码。

## 一、先定产品形态

### 1.1 三个取景，一个会话

以前我把它们当成三个"表面"，各有各的性格——错了。用户说的是对的：**小窗要能对话，主窗要能监控同一件事，两边同步。**

所以正确的模型是：**同一个会话，三种取景（viewport）。切取景不换会话，不重开对话，不丢上下文。**

| 取景 | 尺寸 | 何时出现 | 能干什么 |
|---|---|---|---|
| **舞台 Stage** | 胶囊 32px 高，展开后 ≤ 420×320 | 划线／晃动后就地出现在光标旁 | 看答案、追问一句、执行一个动作。**100+ 次/天，必须最轻** |
| **随行窗 Companion** | 420×640，可停靠屏幕边缘，可 pin | 舞台上按 `⌘↑` 或点"展开" | 完整对话流、思考过程、附件、模型切换 |
| **工作室 Studio** | 全窗口，1200×800 起 | 托盘图标／`Alt+Space` 双击／随行窗右上角"↗" | 对话 + 产物预览 + 收藏箱 + 时间线 + 设置 |

**同步规则**（这条是实现约束，不是设计愿望）：
- 三者共享一个 `session_id`，走同一条 IPC 广播。
- 舞台在追问时，随行窗和工作室的对话流**同步追加**，不需要用户切过去。
- 长任务在舞台上只显示一行进度条 + 剩余步数；要看细节去随行窗/工作室。这就是用户说的"在主屏上监控进度"。
- 关掉舞台 ≠ 结束会话。会话由"目标对象漂移"或用户显式结束来终止。

**铁律不变**：任何功能都不得要求"先打开 Magic Pointer"。工作室是**归宿，不是入口**。


**背景怎么来**（用户问的）——三条路，我建议第 1 条：

1. **用用户自己的桌面壁纸**。取 `HKCU\Control Panel\Desktop\WallPaper`，高斯模糊 60px + 暖色叠加 + 极慢 Ken Burns 位移（40s 一循环，位移 ≤ 3%）。零版权风险，且"这是你的电脑"这个隐喻正好是产品本身。
2. **打包 4 段循环视频**。[Pexels Videos](https://www.pexels.com/videos/) / [Coverr](https://coverr.co/) 免费商用，拉 1080p mp4 转 webm，每段 ≤ 2MB，共 ≤ 8MB。题材照 Oreo：云、水面、风吹的草、窗光落在桌上。
3. **纯 CSS**：两三团 `radial-gradient` 用 60s `ease-in-out` 缓慢漂移 + `feTurbulence` 颗粒。最省事，也最假，只作兜底。

无论哪条，图上必须压一层 `linear-gradient(180deg, rgba(0,0,0,.32), rgba(0,0,0,.12) 40%, rgba(0,0,0,.38))`，否则白字读不了。

## 三、视觉规范：Oreo 暖

### 3.1 色

```css
/* 浅色（默认） */
--paper:        #F2F1ED;  /* 画布，暖灰白。不是 #FFF */
--card:         #FFFFFF;  /* 卡片，纯白 */
--card-sunk:    #FAF9F6;  /* 输入框、次级面板 */
--ink:          #17170F;  /* 正文，暖近黑。不是 #000 */
--ink-2:        #6B6A62;  /* 次要文字 */
--ink-3:        #A3A199;  /* 占位符、时间戳 */
--hairline:     rgba(23,23,15,.08);   /* 唯一的描边 */

/* 深色（另说，但同一套语义） */
--paper-d:      #191815;
--card-d:       #232220;
--ink-d:        #F2F1ED;
```

**判据**：任何一个中性色，色相都必须往暖里偏。全局不出现 `#808080` 这种纯中性灰。

### 3.2 型

| 用途 | 字体 | 号 / 重 |
|---|---|---|
| Hero 大标题 | 衬线，**一个词斜体**（`Instrument Serif` / `Noto Serif SC`） | 56–72px / 400 |
| 卡片标题、按钮 | `Inter` + `Source Han Sans` | 15px / 600 |
| 正文 | 同上 | 15px / 450，行高 1.6 |
| 元信息、时间 | 同上 | 13px / 450，`--ink-3` |
| 路径、ID、数字 | `Cascadia Code`，`tabular-nums` | 13px |

衬线只出现在 Hero 和空态。**卡片里一律无衬线**——Oreo 那几张组件图全是无衬线，混进衬线会碎。

### 3.3 形与影

```css
--r-card:  18px;   /* 卡片 */
--r-input: 22px;   /* 输入框 */
--r-pill:  999px;  /* 药丸、圆按钮 */
--r-chip:  10px;   /* 文件 chip、缩略图 */

/* 卡片阴影：两层，都极淡，色相往暖偏 */
--shadow-card:
  0 1px 2px rgba(23,23,15,.04),
  0 8px 24px -6px rgba(23,23,15,.08);

/* 抬起态（计划卡的"正在进行"那一行） */
--shadow-lift:
  0 2px 4px rgba(23,23,15,.05),
  0 16px 40px -10px rgba(23,23,15,.12);
```

**没有边框**。白卡浮在暖灰底上，靠阴影分离。只有输入框和圆形幽灵按钮用 `--hairline` 一根发丝线。嵌套圆角同心：子 ≤ 父。

### 3.4 图标

照 Oreo 那 1700+ 的路子（`参考/67f0b9e9…png`）：**1.5px 均匀描边、圆头圆角、24×24 网格、纯单色、无填充**。不做渐变图标（Google Workspace 那次评论区骂的就是"渐变让图标分不清"）。

我们要 16 个：晃动唤醒／划线／指向对象／时间线／记忆／剪贴板／产物／四角星／写回／插件／MCP／感知／权限／诊断／写入输入框／交接。生图提示词见 `IMAGE_PROMPTS.md §1`。

### 3.5 头像与能量球 → 直接用 npm 包

用户找的 [`@oreo-design/avatar`](https://github.com/BIAsia/oreo-design-avatar) 是 MIT、零运行时依赖、纯 SVG 输出，6 个形族 × 40 组配色，**由 `variantId` 决定形状抖动**：

```bash
npm i @oreo-design/avatar
```

```ts
import { createAvatar } from "@oreo-design/avatar";
createAvatar({ shape: "bloom", palette: "rose-milk", variantId: hash(objectId), size: 64 });
```

两处用：
1. **对象身份**。时间线每条按"你指过的那个对象"哈希出一颗固定的软渐变球——同一个 Excel 永远同一颗。这比证据缩略图更稳（截图可能过期／涉密），也一眼能认。
2. **能量球四态**。idle/listening/thinking/resolved 用同一个 `variantId` 配四组 `tone`（chroma 0.4→1.0、lightness 递增）+ CSS 呼吸。

**这两条一起把生图需求砍掉两张**（原 §4 能量球、原 §3 应用图标的一部分）。

## 四、新增两个功能

### 4.1 收藏箱 Stash

**用户的原话是问题定义**：截图之后没法直接存本地，得折腾；于是发到微信文件传输助手当仓库。终端里 `Ctrl+V` 粘不进图，得 `Alt+V`。

**市场事实**（我查过）：AI 截图整理产品**全在手机上**——[Sorti](https://letitsorti.com/journal/best-app-to-organize-screenshots-iphone-android)、[SnapStash](https://www.snapstash.app/blog/best-screenshot-organizer-app-iphone)、[Screenshot AI Organizer](https://apps.apple.com/us/app/screenshot-ai-organizer/id6753108940)、[Captr](https://captr.app/)、[Fabric ScreenshotAI](https://fabric.so/screenshot-ai) 全是 iOS/Android。桌面端只有"CleanShot X 截图 + ShotSnap 整理"这种两个工具拼起来。**Windows 上是空的。**

而且它们全靠 OCR 猜内容。我们不猜——**UIA 直接告诉我们你截的是哪个窗口的哪个元素**。这是别人拿不到的。

**流程**：

```
划一笔 / Win+Shift+S 之后
   → 图落到  %LOCALAPPDATA%\MagicPointer\stash\2026-08\
   → 同时记下：源窗口进程名、UIA 元素路径、当时的选区文本、时间
   → AI 一句描述（≤ 20 字）+ 归到四类之一
   → 舞台上弹一条 1.6s 的确认，带「复制路径」
```

**四类**（自动归，可改）：

| 类 | 判据 | 典型 |
|---|---|---|
| **灵感** | 无明确结构、含图或长文 | 看到的好设计、一段话 |
| **交接** | 源自终端／IDE／AI 客户端 | Claude 给的交接、报错栈 |
| **凭证** | 含金额、单号、二维码、日期 | 订单、票据 |
| **素材** | 纯图、无文字或极少 | 配图、参考 |

**为什么这个功能对我们特别顺**：终端粘不进图这件事，我们本来就有"三级写回"——可以直接把**路径**写进终端，而不是图。这是顺手就有的，别人要专门做。

**界面**：工作室侧栏第二项。网格，每个格子是缩略图 + 一句 AI 描述 + 来源应用图标 + 时间。悬停出 `复制路径` / `在资源管理器中显示` / `继续问它`。

### 4.2 实况片段 Live Clip

**用户的场景**：一件事在动，一张截图讲不清；三张关键帧也可能不全。

**做法**：`Win+Shift+L` 录 3–5s（`Windows.Graphics.Capture`，12fps，宽 ≤ 960，128 色）→ 存 GIF + mp4 → 去重帧 → 抽 6–8 关键帧。

**必须说清的约束**：我们**当前的模型（DeepSeek）读不了图**。所以链路只能是：

```
片段 → 抽帧 → 送「有视觉的模型」（用户在设置里配的第二个 profile）
                或 本地 OCR + UIA 快照序列
              → 得到文字描述
              → 回到主模型继续推理
```

没配视觉模型时，退化为"UIA 快照序列 + OCR 差分"——把每帧变化的元素列出来。这条退化路径必须真的实现，否则就是在功能列表上写了个用不了的东西。

**参数**：3–10s，12fps，≤960px 宽，128 色，去重后 30–50% 体积。这几个数是 GIF 工具社区的共识值（[ScreenToGif](https://alternativeto.net/software/screentogif/?p=2) / [ShareX](https://getsharex.com/blog/how-to-record-screen-windows/)），照抄即可。

**放在哪**：收藏箱第五类"片段"，缩略图播首帧，悬停播 GIF。

## 六、动效

沿用 [DESIGN.md](../DESIGN.md#曲线不许手搓) 那套（三条曲线、UI < 300ms、`:active` 按压、hover 门控、`prefers-reduced-motion` 同发）。Oreo 风格额外三条：

1. **卡片进场**：`translateY(8px) + opacity 0` → 0，200ms `--ease-out`，多张错峰 40ms。绝不从 `scale(0)`。
2. **进度条分段填充**：每段 `transform: scaleX()` 独立过渡 180ms，段间延迟 60ms。不是一整条 `width` 动画。
3. **右栏产物推入**：240ms `--ease-drawer`，中栏同时收窄——两者必须同一 duration，否则中间会撕开一条缝。

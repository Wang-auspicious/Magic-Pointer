## 视觉语言：Oreo 暖

> 定于 2026-08-06。**取代**同日早些时候那版"三表面三性格（光迹冷／边注暖／仪器灰）"——冷蓝主调撑不起来，而且三套语言等于没有语言。
> 现在只有一种风格。完整规范（色值、卡片、布局、动效）在 **[design/GUI.md](design/GUI.md)**，这里只留判据。

**五条判据**：

1. **暖，不是白也不是黑。** 画布 `#F2F1ED`，正文 `#17170F`。任何中性色的色相都往暖偏，全局不出现 `#808080`。
2. **白卡浮在暖底上，靠阴影分离，不靠边框。** 两层极淡阴影（`0 1px 2px` + `0 8px 24px -6px`），色相同样往暖偏。只有输入框和圆形幽灵按钮有一根 `--hairline`。
3. **衬线只在 Hero 和空态。** 大标题衬线 + 一个词斜体——这是最省力、回报最大的差异化。**卡片里一律无衬线**，混进去会碎。
4. **彩色只以"浅底深字药丸"出现，大面积不上色。** 六种语义色各有其义（结构层靛／像素琥珀／代码青／成功绿／危险赭红／主操作近黑），见 GUI.md §2.3。不做渐变图标。
5. **深色是它的暗态变体，不是第二套语言。** 同一套语义、同一套形，只换明度。

## 曲线：不许手搓

内置 CSS 缓动太软，缺少"这是故意做的"那种力度。只用这三条：

```css
--ease-out:     cubic-bezier(.23, 1, .32, 1);      /* 进场、出场。默认选它 */
--ease-in-out:  cubic-bezier(.77, 0, .175, 1);     /* 屏幕内移动、变形 */
--ease-drawer:  cubic-bezier(.32, .72, 0, 1);      /* 抽屉、下拉面板 */
```

**永远不要在 UI 上用 `ease-in`**——它开头慢，正好耽误用户盯得最紧的那一刻。`ease-out` 的 200ms 比 `ease-in` 的 200ms *感觉*更快。

需要别的曲线去 [easing.dev](https://easing.dev/) 取，**不要因为眼熟就写 `cubic-bezier(.4,0,.2,1)`**。

## 时长：UI 一律 < 300ms

| 元素 | 时长 |
|---|---|
| 按钮按压反馈 | 100–160ms |
| 提示、小浮层 | 125–200ms |
| 下拉、选择器 | 150–250ms |
| 模态、抽屉 | 200–500ms |

180ms 的下拉比 400ms 的**显得**更灵敏。转圈转得快，加载就显得快——哪怕真实耗时一样。

## 先问：这个该不该有动画

| 用户一天看到几次 | 结论 |
|---|---|
| 100+ 次（快捷键、命令面板开合） | **一律不做动画** |
| 几十次（hover、列表导航） | 只做到几乎察觉不到，或者不做 |
| 偶尔（模态、抽屉、toast） | 正常动画 |
| 罕见/ 首次（引导、成功、庆祝） | 讨喜的预算花在这里 |

**键盘触发的动作是硬性排除项，不是判断题。** Raycast 没有开合动画，对一天开几百次的东西这是对的。

说不出目的就别做。合法目的只有：反馈、空间连续性、状态指示、防止内容瞬移、解释说明（仅营销/引导）、讨喜（仅限罕见层）。

## 本项目的具体约束

- **气泡是 100+ 次/天的东西**。它的开合只能有极轻的 width transition，不能加花哨进场。真正该花动效预算的是**回答面板展开**和**chip 入流**——那是偶尔发生、且需要解释"东西从哪来"的地方。
- **面板的 `transform-origin` 必须在气泡处**，这样它读起来是"从气泡里展开"，不是凭空放大。模态例外，保持居中。
- **绝不从 `scale(0)` 进场**，从 `.95`–`.97` 起配 `opacity:0`。现实里没有东西从虚无中出现。
- **只动 `transform` 和 `opacity`**。动 `width/height/top/left/margin/padding` 会触发 layout + paint。胶囊宽度是唯一例外，且必须用可打断的 transition。
- **可快速重复触发的用 transition，不用 keyframes**。keyframes 被打断会从头开始，transition 会从当前值接上。
- **按压反馈**：所有可按的东西 `:active { transform: scale(.97) }`，140–160ms。
- **hover 动效必须门控** `@media (hover: hover) and (pointer: fine)`，否则触屏点一下会触发假 hover。
- **减弱动效要一起发**，不是后补。`prefers-reduced-motion` 下是**更少更轻**，不是全关——保留不透明度和颜色过渡，去掉位移。
- **错峰 30–80ms**。一堆元素同时进场很廉价。但错峰是装饰性的，绝不能阻塞交互。
- **不对称时长**：慢在用户决策的那段（按住确认 1.6s linear），快在系统响应那段（松手 200ms ease-out）。
- **不要用 CSS 变量驱动子元素的 transform**——父级变量一变，所有子元素都要重算样式。直接设在元素上。

## 玻璃材质：必须两层

浮层飘在**别人的窗口**上，背景我们控制不了。单层半透明会让底下的正文透上来和自己的字叠在一起。

正确做法是两层：模糊层负责质感，文字底下另铺一块高不透明度的板负责可读；深背景上自动加厚。Apple 给 Liquid Glass 补的不透明度滑块、Golden Gate 把侧栏从悬浮改回贴边，都是在补这个。微软干脆规定真模糊（Acrylic）只能用在临时浮层上，持久 chrome 用 Mica（取壁纸颜色但不透实时内容）。

**推论：气泡/面板可以是玻璃，设置页不做实时透明。**

透明 Windows 窗口上 CSS 投影会变成矩形残影——这条是本仓库踩过的坑，玻璃层靠 `inset` 高光和 hairline 边框做分离。

## 视觉细节

- **分层阴影**：环境光（远、大、淡）+ 直接光（近、小、实），两条一起写。
- **半透明边框 + 阴影**做锐利边缘，不要纯色硬边。
- **嵌套圆角同心**：子元素圆角 ≤ 父元素。
- **色相一致**：边框、阴影、次要文字都往背景色相上偏，不要用中性灰。
- **数字对比处用 `font-variant-numeric: tabular-nums`**。
- **正文字重 500 起**，不是 400——半透明浮层上 400 发虚。
- 省略号用 `…` 不是 `...`；会打开后续操作的选项以 `…` 结尾。
- **骨架屏必须和最终内容同形**，否则会有布局跳动。
- `:hover` / `:active` / `:focus` 都要**提高**对比度，不是换个颜色。
- 焦点环用 `:focus-visible`，**绝不 `outline:none` 而不给替代**。

## 怎么检查自己做的动效

1. **放慢 2–5 倍看**。全速看不出的时序问题，慢放一眼就露（`document.getAnimations().forEach(a => a.playbackRate = .2)`）。
2. 慢放时specifically看：颜色过渡是不是能看见两个状态在叠；`transform-origin` 对不对；多个属性有没有同步。
3. **第二天再看一遍**。当天看不出的毛病，隔一天用新鲜的眼睛能看出来。
4. 手势类必须**上真机**测。
